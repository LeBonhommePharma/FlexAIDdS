# Audit: 04735c31b — Add: ProtocolConfig chunk 3 + RUN_RECEIPT.json on DatasetRunner paths

## Summary (2–4 sentences)
Commit `04735c31b42c80309626aa2b9af6635c1f1dbfaf` finishes ProtocolConfig **chunk 3**: all remaining science-knob `getenv` sites in `LIB/config_parser.cpp` move to a single `ProtocolConfig` snapshot (`apply_config(..., const ProtocolConfig*)`), and `DatasetRunner::run()` emits C0-aligned `RUN_RECEIPT.json` (plus legacy `provenance.json`) with matrix/binary hashes, temperature, pop/gen/restarts, seed flags, git commit, and nested `protocol_config`. **Ranking/scoring algorithms are not modified** — only the override *source path* (raw env → typed snapshot). Reproducibility is materially improved, with residual dual-truth risks around receipt vs runtime `seed_elitism`, C0-vs-C++ receipt schema non-identity, incomplete `from_json` round-trip tests for chunk-3 fields, and silent empty hashes when matrix/binary resolve fails.

## Severity: LOW–MEDIUM

(Net positive for dual-protocol hardening and provenance; not claim-blocking by itself. Fix dual-truth seed_elitism and receipt merge policy before treating RUN_RECEIPT as a sole claim contract.)

## Findings

### F1. Ranking neutrality: **PASS** (INFO / positive)
- Evidence: Diff is confined to ProtocolConfig / config_parser / DatasetRunner provenance / tests / docs / CMake. `config_parser` still sets:
  1. JSON `force_cf_rank_emission` / `classic_entropy_ranking`
  2. then optional `proto.force_cf_rank_emission`
  3. then optional `proto.classic_entropy_ranking` (**last wins**, maps classic=false → CF emission)
  Same order as pre-chunk-3 raw `getenv`. Dual-set env `FORCE=1` + `CLASSIC=1` still ends at entropy ranking; `CLASSIC=0` still ends at CF emission.
- Why it matters: AGENTS.md forbids silent ranking/clustering changes. This commit’s product ranking path is default-identical when env is unset (nullopt → leave JSON-derived `FA->force_cf_rank_emission`).
- Fix recommendation: None for ranking. Keep the “unset → no override” optional-bool semantics if future chunks add more gates.

### F2. RUN_RECEIPT completeness vs stated C0 alignment (MEDIUM)
- Evidence — **present in C++ receipt** (`RunReceipt.h` / `build_run_receipt_json`):

  | Field | Present | Source |
  |-------|---------|--------|
  | `schema_version` | yes (`1`) | constant |
  | `run_id`, `started_utc`, `output`, `dataset`, `mode` | yes | DatasetRunner |
  | **`temperature_K`** | yes | `DockingConfig::temperature` |
  | **`pop` / `gen` / `restarts`** | yes | config + `protocol_cfg_.restarts` |
  | **`seed_base` / `seed_elitism`** | yes | protocol + mode force (see F3) |
  | **`matrix_path` / `matrix_md5` / `matrix_sha256`** | yes | matrix resolve + hash |
  | **`binary_path` / `binary_sha256`** | yes | resolved FlexAID/FlexAIDdS + hash |
  | `runner_path` / `runner_sha256` | yes (Apple/Linux) | `_NSGetExecutablePath` / `/proc/self/exe` |
  | `git_commit` | yes (best-effort) | `git rev-parse HEAD` via `popen` |
  | `oracle_site_dir` (+ set flag) | yes | protocol |
  | nested **`protocol_config`** | yes | full `ProtocolConfig::to_json()` |

- Evidence — **C0 launch receipt** (`scripts/run_C0_claim_clean.sh`) also carries claim-only keys C++ does **not** emit: `storage`, `icloud_mirror`, `native_seed_frac`, top-level `eval_scale_dihedral` / `budget_scale` / `max_results`, `manifest`, `claim_path`, `anti_hang`, `supersedes`, nested `env{…}`. Those budget knobs *do* appear under nested `protocol_config` in the C++ path (`eval_scale_dihedral`, `budget_scale`, `seed_elitism`, …) but **not** as top-level C0 twins.
- Why it matters for science/repro: Docs claim “C0-aligned.” Schema is a **superset on science knobs** (protocol snapshot, matrix path, seed_base) and a **subset on campaign ops**. Any aggregator that requires C0-only keys will break on DatasetRunner-only campaigns, and vice versa.
- Fix recommendation: Document two profiles (`schema_version` + `receipt_profile: "dataset_runner"|"c0_claim"`) or merge (read-modify-write) when overwriting an existing receipt so C0 campaign fields survive C++ re-write. Optionally mirror C0 top-level budget keys as aliases for parsers.

### F3. Dual-truth: receipt `seed_elitism` vs runtime pose-selection override (MEDIUM)
- Evidence — **receipt** (`DatasetRunner.cpp` ~4965–4987):
  - `ORACLE_CEILING` → `receipt.seed_elitism = true`
  - `DEFINED_CLEFT_REDOCK` / `AUTONOMOUS` → `false`
  - Nested `protocol_config.seed_elitism` remains the **env snapshot** (default true) and is **not** rewritten to match the mode force.
- Evidence — **runtime pose election** (~6365–6371):
  ```cpp
  const int sel_elitism_ovr =
      (config.mode == BenchmarkMode::ORACLE_CEILING ||
       config.mode == BenchmarkMode::AUTONOMOUS ||
       config.mode == BenchmarkMode::DEFINED_CLEFT_REDOCK) ? 0 : -1;
  ```
  All three named modes force **pose-selection elitism OFF** (`0`). For **oracle**, receipt claims `seed_elitism: 1` while election path forces off.
- Why it matters: Provenance lies are worse than missing fields. Claim audits that trust top-level `seed_elitism` for oracle runs will mis-state the actual selector policy. Nested `protocol_config.seed_elitism` can disagree with top-level even when runtime matches top-level (defined-cleft).
- Fix recommendation: (a) Align receipt mode force with `sel_elitism_ovr` (oracle → 0 if that is the real product path), **or** (b) rename receipt field to `seed_elitism_protocol_intent` vs `pose_selection_seed_elitism_effective` and set both from the same helper used by election. Also overwrite nested `protocol.seed_elitism` before serialize, or document that nested is pre-mode-force env truth.

### F4. Hashes can be silently empty; MD5 still shell-only (LOW–MEDIUM)
- Evidence: `md5_of` / `sha256_of` return `""` when path missing or hash tools fail. SHA-256 prefers `flexaids::posebust::sha256_file` then shell; MD5 is **only** `md5 -q` / `md5sum` shell. Matrix resolve can fall through to empty path → empty digests still written as JSON strings.
- Why it matters: A receipt with `"matrix_md5": ""` / `"binary_sha256": ""` looks complete but fails pin verification. Claim aggregators (`scripts/aggregate_claim_metrics.py`) that pin matrix MD5 will not fail closed on empty strings unless they check explicitly.
- Fix recommendation: Fail-closed option (`FLEXAIDDS_RECEIPT_REQUIRE_HASHES=1`) or write `null` + `"hash_status": "missing"` when digests empty. Prefer in-process MD5 as well for parity with SHA-256 (and CloudDocs hang safety if path ever points at iCloud — currently DatasetRunner should stay local-first).

### F5. Base `pop`/`gen` on receipt may not be effective DoF-scaled budget (LOW)
- Evidence: Receipt uses `config.ga_population` / `config.ga_generations` at `run()` entry. Per-entry DoF scaling via `protocol_cfg_.eval_scale_dihedral` / `budget_scale` happens later when building child commands (DatasetRunner dock path ~5437+). Nested `protocol_config` records *scale mode*, not realized pop×DoF per target.
- Why it matters: AGENTS.md DoF budget rule — claim runs fix generations and scale **population**. A receipt that prints base `pop=1000, gen=6000` without `[EVAL-BUDGET]` effective values invites the exact misread the project already documents.
- Fix recommendation: Add `pop_base`/`gen_base` plus optional `eval_budget_note`, or emit per-target receipts / log path to `[EVAL-BUDGET]` lines. At minimum document that top-level pop/gen are DockingConfig bases.

### F6. `from_json` fidelity for chunk-3 fields (LOW–MEDIUM)
- Evidence:
  - Full `to_json()` always emits `vct_entropy_weight`, `vct_entropy_weight_set`, `n_elite`, `n_elite_set`, and optional ranking knobs as `null` or bool/number. `from_json` sets `*_set = true` when the value key is present, then **overwrites** from the explicit `*_set` key — order is correct for full round-trips of emitted JSON.
  - Partial hand-written JSON with only `"vct_entropy_weight": 0.0` (no `_set`) forces override gate true (presence semantics — analogous to historical getenv presence). Acceptable if documented.
  - Optional ranking fields (`force_cf_rank_emission`, `classic_entropy_ranking`, `entropy_weight`, `diversity_monitoring`) correctly use null → `nullopt`.
  - Pre-existing gap: `parallel_restarts_explicit` is not serialized.
  - **Tests:** `JsonRoundTrip` does **not** assert chunk-3 fields or `*_set` flags. `Chunk3RankingAndAblationKnobs` only tests `from_env`, not `to_json`/`from_json`. No test that `apply_config` maps protocol snapshot onto `FA_Global`/`GB_Global` (no integration with stub FA/GB).
- Why it matters: Receipt embeds `protocol_config` as the durable dual-protocol pin. If rehydration is used later for exact replay, untested fields can silently drop or mis-set override gates (`n_elite_set` / `vct_entropy_weight_set`).
- Fix recommendation: Extend `JsonRoundTrip` (or new test) with force_cf / classic / entropy_weight / diversity / both `*_set` false and true paths; add a thin `apply_config` unit test with fake FA/GB and a fixed ProtocolConfig pointer (no env).

### F7. Dual-protocol residual after chunk 3 (LOW / residual risk)
- Evidence (positive): `config_parser` has **0** residual `FLEXAIDDS_*` getenv. `apply_config` takes one snapshot at entry (or caller-supplied pointer). `top.cpp` snapshots once and passes it. `DatasetRunner::run()` re-snapshots `protocol_cfg_` at entry and embeds that object in the receipt.
- Residual: child FlexAID process re-enters `top` → `from_env()` again (not the parent’s in-memory snapshot). Mid-campaign `setenv` in the parent environment after receipt write but before fork still dual-protocols engine vs receipt. Documented residual audit-trio getenv ~11 (BINARY, HOME, OMP, infra) remain by design.
- Why it matters: Chunk 3 closes mid-`apply_config` dual-path; it does **not** freeze the child process to the receipt’s nested JSON (no “replay from receipt only” path).
- Fix recommendation: Future chunk — optional `FLEXAIDDS_PROTOCOL_JSON` / load ProtocolConfig from receipt for child engines; or write `protocol_config` to a side file and pass path. Until then, freeze env before launch (C0 already exports a fixed env block).

### F8. Receipt write is best-effort overwrite at run start (LOW)
- Evidence: `write_run_receipt` opens `RUN_RECEIPT.json` with truncating `ofstream` (no merge). Failure returns false and logs WARN; docking continues. Written **before** docking loop — good for crash provenance, but final effective hashes of per-target outputs are not appended. No end-of-run receipt refresh.
- Why it matters: If C0 Python wrote a claim receipt first and DatasetRunner later runs into the same `output_dir`, C0-only keys are destroyed (F2). Crash after start still has hashes of binary/matrix at start — good.
- Fix recommendation: Merge-preserving write when file exists; optional end-of-run receipt with `finished_utc` + summary counts.

### F9. Tests adequacy (LOW)
- Evidence: New tests cover:
  - `from_env` for chunk-3 ranking/ablation knobs
  - `build_run_receipt_json` substring keys (schema, temp, pop/gen, seed, matrix/binary hashes, git, protocol_config)
  - `write_run_receipt` creates both files on disk
- Missing: apply_config integration; from_json chunk-3 round-trip; mode-aware seed_elitism receipt helper; empty-hash behavior; DatasetRunner end-to-end receipt (would need heavier fixture).
- Why it matters: CI will catch string-key regressions in the builder, not semantic dual-truth (F3) or override application.
- Fix recommendation: As in F6; add a pure unit test of a shared `effective_seed_elitism(mode, protocol)` used by both receipt and selector.

### F10. Scientific language / CF proxy (INFO / pass)
- Evidence: Commit does not rename free energy as ΔG. Ranking knobs still gate `FA->force_cf_rank_emission` (CF emission rollback vs classic soft-β entropy ranking). Docs explicitly: “Ranking algorithm is unchanged — only the source of the override moves.” Nested protocol can still contain thermo/Shannon flags; receipt does not invent thermodynamic claims.
- Fix recommendation: Keep claim prose distinguishing CF/contact-function scoring proxy vs ensemble free-energy estimates when reading receipts.

### F11. Security / hygiene (INFO)
- Evidence: No secrets, no machine-absolute paths baked into new sources. Shell hashing uses `shell_quote`. `popen` for git/hash remains (pre-existing pattern). Test uses `temp_directory_path` + pid, cleans up.
- Fix recommendation: N/A for this commit.

## Ranking/scoring impact: **NO**

Default product ranking (JSON defaults, env unset) is unchanged. When env overrides are set, semantics match pre-chunk-3 getenv (including classic-last-wins). No clustering, Voronoi CF, BindingMode, or GA fitness formula edits in this commit.

## Reproducibility impact: **YES** (net positive)

Positive: single ProtocolConfig snapshot in apply path; RUN_RECEIPT with matrix/binary digests, T, GA base budget, seed_base, mode, git, full protocol JSON; legacy provenance retained; PoseBust in-process SHA-256 preferred. Negative: dual-truth seed_elitism for oracle; C0/C++ schema split + overwrite; silent empty hashes; base pop/gen vs effective budget; child still re-reads env.

## Tests adequate: **PARTIAL**

Adequate for builder key presence and env adapter; inadequate for apply_config wiring, from_json chunk-3, and receipt↔runtime seed_elitism consistency.

## Verdict: **MERGE_OK** (with follow-ups)

Safe and desirable as dual-protocol / provenance infrastructure. Does **not** by itself alter science ranking. Before treating `RUN_RECEIPT.json` as the sole claim contract for oracle or C0 campaigns, address **F3** (seed_elitism dual-truth) and **F2/F8** (schema profile / non-destructive merge). Strengthen **F6** tests when replay-from-JSON becomes a supported path.

### Suggested follow-up order
1. Single helper for effective seed_elitism used by receipt + pose election; eliminate nested/top-level disagreement.
2. Receipt merge policy when file already exists (preserve C0 campaign keys).
3. Fail-closed or null digests when matrix/binary hash empty.
4. Unit tests: ProtocolConfig chunk-3 JSON round-trip + apply_config with injected snapshot.
5. Optional: document pop/gen as base; point auditors at `[EVAL-BUDGET]` / nested eval_scale flags.
