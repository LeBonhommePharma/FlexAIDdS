### F2. “False apo” / byte-identity is **not** over-claimed (INFO / positive)
- Evidence:
  - Docstring + CANONICAL + summary `interpretation` state explicitly: apo byte-identity to deposit alone is **not** a fail when the cognate ligand is already absent from the deposit PDB (ligand lives in CIF/SDF).
  - Status logic (`analyze_target`): identity only annotates notes (`apo_byte_identical_to_deposit` + `identity_ok_if_ligand_absent_from_pdb`); fail requires residual residue-name hits or **strong** coord match.
  - Spot-check `1G9V`: apo SHA == deposit SHA; cognate `RQ3` absent from both; HEM cofactor retained (in `STD_RESIDUES`) — correct “deposit-as-apo” semantics, not a silent ligand contamination.
- Why it matters: Bulk treating 83 identical apos as “must strip / corrupt” would be the real data disaster. The commit correctly prevents that false positive.
- Fix recommendation: Keep this interpretation next to any campaign prose that says “apo receptor.” Prefer language: “deposit PDB without cognate ligand atoms (ligand from SDF/CIF)” when describing the 83/85 set.

### F3. `1TW6` non-identity is a true peptide strip; deposit still holds the ligand (LOW–MEDIUM documentation gap)
- Evidence (spot-check on tree files):
  - Apo SHA ≠ deposit SHA (sizes 124501 vs 126688).
  - Deposit-only atoms: **27** — chain **C** peptide `ALA1–VAL2–PRO3–ILE4` (counts 5+7+7+8).
  - SDF title is `ALA` with **27** coords; deposit coord match @0.35 Å = **27/27** on that peptide; **apo coord match = 0**.
  - Validator: `peptide_like_ligand_title` → residue-name match disabled (avoids false fail on protein ALA); residual gate uses coords only → `pass`. Correct for **apo**.
- Why it matters:
  - CANONICAL row for `1TW6` (“no residual coords in apo”) is **true**.
  - The SDF title `ALA` under-describes a 4-residue peptide ligand; residue-name strip would only remove `ALA` if forced, not VAL/PRO/ILE — conservative peptide block (`PEPTIDE_LIKE` + no `--force-peptide`) is therefore mandatory, not optional safety theater.
  - Anyone docking against `1TW6.pdb` (deposit) rather than `1TW6_apo.pdb` would still have cognate peptide present — a path/usage footgun outside this script’s fail gate.
- Fix recommendation: In CANONICAL (future docs commit), note deposit still contains chain-C tetrapeptide; ligand title `ALA` is first-residue SDF naming; docking must use `*_apo.pdb`. Optional validator note field: `deposit_still_has_coord_match` for non-identical pairs (report-only).

### F4. `2BYS` non-identity is chain trim / prep, not residual `LOB` (INFO)
- Evidence: Apo 3336 atoms (chains A,E) vs deposit 16682 (chains A–J); neither file text contains `LOB`; coord match apo@0.35 = 0. Status `pass` is correct. CANONICAL “historical chain trim / prep” matches the atom/chain evidence.
- Fix recommendation: None beyond retaining the non-identical table.

### F5. Peptide-like ligand titles: residual metric is coord-only by design (LOW)
- Evidence: `PEPTIDE_LIKE` short-circuits residue-name collection (`lig_atoms = []`). Affected Astex titles in STD/peptide set: **`1TW6`/`ALA`**, **`1X8X`/`TYR`** only.
  - `1X8X`: apo byte-identical to deposit; TYR protein atoms exist (108) but SDF coords match **0** even @2.0 Å → pass is correct (cognate not in PDB frame).
  - `ligand_atoms_in_apo` is therefore **always 0** for peptide-like titles, even if a future bad apo reintroduced a same-name HETATM without coord agreement.
- Why it matters: CANONICAL “Ligand residue atoms remaining in apo | 0/85” is true under the **script metric**, not under a naïve “count all ALA/TYR atoms.” Strong coord match still fails the gate (`coord_hits >= max(3, max(1, len(lig_coords)//2))`).
- Fix recommendation: Keep dual metrics in the table (residue-name remaining **and** `n_coord_match`). Do not claim “zero peptide atoms in apo” — claim “zero cognate residual by name (non-peptide) + zero coord matches.”

### F6. Gate strictness: `--strict` is largely redundant; warn is soft (LOW)
- Evidence (`main` exit policy):
  ```text
  if n_fail and not args.allow_fail: return 1
  if args.strict and n_fail and not args.allow_fail: return 1  # same outcome
  ```
  - Default already exits **1** on any `status=fail` unless `--allow-fail`.
  - `--strict` does **not** promote `warn` → fail.
  - `pass_fail` maps `warn` → `"pass"` for the binary column.
  - Missing apo or missing ligand SDF/MOL2 → `status=warn` only (would **not** trip default/`--strict` exit).
  - Weak coord hits (`0 < coord_hits < strong threshold`) → `warn` only.
- Why it matters: Mission language “strict gate” suggests fail-closed on more than residual-ligand `fail`. As shipped, strict = explicit alias of default fail exit. A corrupted tree with missing apos could still exit 0 with all present rows pass and missing ones warn… actually missing files set warn per target, and `n_fail` stays 0 → **exit 0**. That is the main strictness hole.
- Fix recommendation (future, not this commit): `--strict` should fail on `n_warn>0` and/or missing required files; or introduce `--strict-files`. Document that current `--strict` ≡ “nonzero exit on residual-ligand fail.”

### F7. Strip path is intentionally conservative and pilot-capped (INFO / positive)
- Evidence:
  - `--fix-dry-run` vs `--write`/`--fix`; mutual exclusion error.
  - `plan_strip`: only `status=fail`, non-peptide title, `ligand_atoms_in_apo>0`; coord-only fails → `coord_only_needs_manual_review`.
  - Real write capped at **3** unless `--all-safe`.
  - Peptide requires `--force-peptide` (critical given F3).
- Why it matters: Prevents bulk-rewrite of the 83 identical deposit-as-apo files and prevents mass-deleting protein ALA/TYR. Aligns with CANONICAL “Do not bulk-rewrite apo… Do not delete data trees.”
- Fix recommendation: None for safety design. Optional: refuse `--write` when `n_fail==0` with a clear message (current behavior is no-op applied=0).

### F8. Minor metric/naming imprecisions (LOW)
- Evidence:
  - Field `identical_sha_to_deposit` is set from `filecmp.cmp(..., shallow=False)`, not from comparing the computed SHA256 strings (SHA256 still reported in CSV). Functionally equivalent for on-disk files; name overclaims “sha.”
  - `n_ligand_atoms_remaining` in summary counts residue-name hits only, not coord-match atoms (coord has its own `n_coord_match`).
  - `nonstd_hetatm_*` is informational: `1N1M` HG×4, `1YV3` VO4×1; neither is the cognate ligand. `HG` not in `STD_RESIDUES` (ions list incomplete for mercury) — noise only.
  - SDF parser is V2000-only; fine for current 85, latent gap if V3000 enters the tree.
  - No unit tests under `tests/` / `python/tests/` for this validator (grep: script self-refs only).
- Why it matters: Downstream consumers trusting `identical_sha_*` as hash equality or `n_ligand_atoms_remaining` as “any residual” could mis-summarize; lack of tests risks gate drift on refactor.
- Fix recommendation: Rename or dual-set identity from sha equality; add pure-Python tests with tiny synthetic apo/deposit/ligand fixtures (identical OK, residual HETATM fail, peptide coord fail, missing file warn/strict).
