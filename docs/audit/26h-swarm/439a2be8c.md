## 3. File-by-file review

### 3.1 `scripts/validate_astex_apo_strip.py` (+788)

#### Architecture

| Component | Behaviour |
|-----------|-----------|
| Tree default | `benchmarks/astex_diverse/astex_diverse/<PDB>/` (matches `CANONICAL.md`) |
| Ligand resolve | Prefer `<PDB>_ligand.sdf`, else MOL2, else glob fallbacks |
| Residue residual | APO atoms whose 3-letter resname equals SDF/MOL2 **title** (skipped for peptide-like AA titles) |
| Coordinate residual | PDB atoms within **0.35 Å** of any ligand SDF/MOL2 atom (O(N×M) brute force) |
| Identity | `filecmp.cmp(apo, deposit, shallow=False)` **plus** separate SHA-256 fields |
| Status | `fail` = resname hits or strong coord match; `warn` = weak coords / missing files / peptide without coords; `pass` otherwise |
| Binary gate | `pass_fail = "fail" if status=="fail" else "pass"` (**warn → pass**) |
| Write safety | Default report-only; real strip needs `--write`/`--fix`; pilot ≤3 unless `--all-safe`; peptide skip unless `--force-peptide`; `.bak` once |
| Exit | Any `status=fail` → exit 1 unless `--allow-fail`; path errors → 2 |

#### Strengths

- **Correct scientific interpretation of apo==deposit.** Identity alone is not a residual-ligand fail when the cognate HETATM already lives only in CIF/SDF. Documented in module docstring, JSON `interpretation`, and CANONICAL.md.
- **Peptide collision handling.** Titles in standard AA codes (`PEPTIDE_LIKE`) disable resname matching (avoids false-failing every ALA in the receptor). Coord match remains the residual detector for those cases.
- **Conservative mutation path.** Report-only default; dry-run describes; write is pilot-capped; backups; coord-only fails are **not** auto-stripped (`coord_only_needs_manual_review`).
- **Dual identity reporting.** Mission alias `identical_sha_to_deposit` + legacy `apo_identical_to_deposit`; both SHA digests stored for offline audit.
- **Regeneratable artifacts.** CSV columns = full `TargetReport` dataclass; summary JSON has fail list, non-identical list, worst offenders, flags for how the run was invoked (`strict`, `write`, …).
- **No CloudDocs walks.** Local `Path.iterdir` / file reads only under the repo tree — compliant with local-first / thin-iCloud policy.

#### Status / fail logic (reproduced)

```
missing apo or ligand          → warn
resname ligand atoms > 0       → fail   (non-peptide titles only)
coord_hits ≥ max(3, n_lig//2)  → fail   (+ strong_coord_match note)
0 < coord_hits < threshold     → warn
peptide title, no coords       → warn   (+ peptide_needs_manual_review)
else (incl. identical deposit) → pass
```

Strong-coord threshold is reasonable for small-molecule Astex ligands (typical SDF atom counts ~20–40 → threshold ~10–20).

## 4. Findings

### F1. Residual-ligand claim verified on live tree (INFO — good)

- Evidence: Re-run `--strict` → exit 0; CSV 85×`pass`; independent spot checks:
  - **Non-peptide set:** among apo-identical targets, deposit PDB has **0** ligand-resname hits and **0** coord hits at 0.35 Å for cognate SDF (ligand already absent from deposit PDB).
  - **1TW6 (ALA peptide):** deposit has **27** coord matches to SDF; apo has **0**. Apo is smaller (1537 vs 1564 atoms) — peptide ligand stripped from apo while deposit still carries it. Resname “ALA” would hit ~80 protein atoms if naïvely used; peptide path correctly uses coords only.
  - **2BYS (LOB):** apo 3336 ATOM vs deposit 16682 ATOM (historical chain trim / prep); LOB resname and coords absent from both apo and this deposit PDB snapshot.
- Why it matters: Three-engine / claim docking inputs are the apo receptors; residual cognate ligand would corrupt self-docking RMSD and site definition. Gate closes that class of silent data bug for the 85-set as currently shipped.
- Fix recommendation: None for the claim itself. Re-run after any structure tree edit; regenerate CSV+JSON+checksums together (already stated in CANONICAL).

### F2. `--strict` does not fail on missing data (`warn` → exit 0) (MEDIUM / P2)

- Evidence:
  ```python
  if not apo.is_file() or ligand_path is None:
      status = "warn"
  ...
  pass_fail = "fail" if status == "fail" else "pass"
  ...
  if n_fail and not args.allow_fail:
      return 1
  ```
  Missing apo or ligand → `warn` → counted as binary **pass** → process exit **0** even with `--strict`.
- Why it matters: A partially deleted or empty tree, or a broken download that leaves only deposit PDBs, would **silently green** the science gate. Mission language (“strict gate”) oversells completeness.
- Fix recommendation:
  1. Treat `missing_apo` / `missing_ligand_sdf_mol2` as `fail` under `--strict` (or a new `--strict-data` flag).
  2. Require `n_targets == 85` (or match `astex_diverse_codes()`) under `--strict`.
  3. Optionally fail if `n_warn > 0` when `--strict` is set.
  4. Document that current `--strict` is **residual-ligand-only**, not full data-completeness.

### F3. `identical_sha_to_deposit` is a misnomer (LOW / P3)

- Evidence: Field is set from `filecmp.cmp(..., shallow=False)`, not from comparing `apo_sha256`/`deposit_sha256`. Digests are computed and happen to agree with the boolean on this tree.
- Why it matters: Agents/docs reading the column name may assume hash equality without reading code; future shallow-copy / hardlink edge cases could theoretically diverge if someone changed the identity predicate without updating SHA fields.
- Fix recommendation: Rename to `identical_bytes_to_deposit` **or** set the flag from `apo_sha256 == deposit_sha256` after both digests are computed (single source of truth). Keep the old name as a deprecated alias if any external consumer exists (none found in-repo beyond these artifacts).

### F4. No unit tests and no CI wire (MEDIUM / P2)

- Evidence: `rg` finds no `validate_astex_apo_strip` / `astex_apo_strip` under `tests/`, `python/tests/`, or `.github/workflows/`. Only CANONICAL + the script itself reference the gate.
- Why it matters: Status vocabulary already drifted once (`ok` → `pass` between `65afedcb2` and `fe0b961e4`). Without tests, peptide skip, strong-coord threshold, pilot write cap, and exit codes can regress unnoticed. Committed CSV/JSON can go stale relative to the tree.
- Fix recommendation:
  - Pure unit tests with tiny synthetic PDB/SDF fixtures (fail path: residual HETATM; pass path: stripped; peptide path: ALA protein + peptide coords; missing-file warn/fail).
  - Optional CI job or skill step: `python3 scripts/validate_astex_apo_strip.py --strict` when the Astex tree is present (or fixture subset).
  - Optional: `generate_astex_manifest.py --check` coupling so apo edits force checksum refresh.

### F5. Peptide ligand residual detection is uneven (1X8X gap) (MEDIUM / P2)

- Evidence:
  | PDB | Title | apo vs deposit | apo coord@0.35 | dep coord@0.35 |
  |-----|-------|----------------|----------------|----------------|
  | 1TW6 | ALA | different | 0 | **27** (good: residual only on deposit) |
  | 1X8X | TYR | **identical** | 0 | 0 |

  1X8X SDF claims extraction from HETATM (`FLEXAIDDS_LIGAND_EXTRACTOR_V4`), 13 atoms, title `TYR`. Nearest deposit atom to first SDF coordinate is ~2.73 Å (GLN); no match even at 2.0 Å. Deposit HETATM counter is empty; single chain A with 322 polymer residues. So **coord residual cannot confirm** presence/absence of the cognate free-TYR ligand — only that current SDF frame is not in the PDB snapshot.
- Why it matters: DatasetRunner C++ already special-cases peptide ligands (e.g. 1TW6 Smac AVPI as ATOM chain C). The strip validator’s peptide path is adequate when SDF coords still match deposit (1TW6) but is a **no-op detector** when SDF frame ≠ PDB frame (1X8X). Residual free amino-acid ligand would not be caught by resname (disabled) nor coords (no match).
- Fix recommendation:
  1. For peptide-like titles, also compare against **chain-level short peptide** logic aligned with `collect_peptide_ligand_atoms` in `LIB/DatasetRunner.cpp` (short all-AA chain beside a large receptor).
  2. Or cross-check CIF HETATM / non-polymer entities for residue codes and occupancy.
  3. Flag peptide targets with `coord_match==0` and `identical_sha_to_deposit` as `warn` + `peptide_frame_unverified` rather than silent `pass` when SDF header says HETATM-extracted.
  4. At minimum document 1X8X as “coord-unverified peptide title” in CANONICAL.

### F6. Global residue-name strip can over-delete (LOW / P3)

- Evidence: `strip_ligand_residue` removes **every** ATOM/HETATM whose resname equals the ligand title, all chains/resseqs.
- Why it matters: Safe for unique 3-letter druglike codes on this set (0 planned strips). Dangerous if a cognate code collides with a cofactor copy, crystal mate, or covalently modified residue with the same 3-letter name. Peptide force-strip would nuke the entire protein sequence for that AA.
- Fix recommendation: Scope strip by (chain, resseq) sets discovered during residual detection; never enable `--force-peptide` in automation; keep pilot cap.

### F7. SDF title is sole chemical identity key (LOW / P3)

- Evidence: `sdf_title` = first line of SDF. All 85 titles are length-3 and match intended HET codes on this tree. No validation that title ∈ {PDB HET codes} or matches CIF `_pdbx_nonpoly_scheme`.
- Why it matters: A mis-titled SDF (PDB ID, long name, SMILES) would disable resname residual detection and only leave coord matching.
- Fix recommendation: Warn/fail if title length ∉ {1,2,3} or title not alphanumeric; optional cross-check against nonstd HETATM names in deposit.

### F8. `pass_fail` collapses `warn` (LOW / P3)

- Evidence: Binary column maps warn→pass; only `status` preserves three-way signal.
- Why it matters: Downstream tools filtering on `pass_fail` alone hide missing-file and weak-coord cases.
- Fix recommendation: Prefer `status` in any CI gate; or define `pass_fail` as fail for both `fail` and `warn` under strict mode.

### F9. Dead / redundant exit branch for `--strict` (INFO)

- Evidence: Default already exits 1 on `n_fail`; second `if args.strict and n_fail` is unreachable after the first return. Docstring still useful as mission wording.
- Fix recommendation: Simplify to one exit policy block; keep `--strict` as documentation alias or make it the **stricter** completeness gate (see F2).

### F10. SDF V2000 only; no altLoc / multi-model handling (LOW / P3)

- Evidence: Atom count from columns 0:3 of counts line; no V3000; PDB parser ignores altLoc occupancy filtering and MODEL records.
- Why it matters: Fine for current Astex extracts (V2000, single model). Would under-count or double-count on messier deposits.
- Fix recommendation: Document limitation; add V3000 if re-extracting ligands.

### F11. Target set discovery vs C++ list (INFO — currently OK)

- Evidence: `discover_targets(tree)` returns 85 IDs; `DatasetRunner::astex_diverse_codes()` returns the **same set** (symmetric difference empty on this host).
- Why it matters: Discovery is filesystem-based (dirs with apo or deposit). Extra/missing directories would change N without failing the gate (ties to F2).
- Fix recommendation: Under `--strict`, assert equality with a frozen list or parse YAML/`astex_diverse_codes` export.

### F12. Incidental nonstd HETATM (HG, VO4) not cognate (INFO)

- Evidence: Aggregate nonstd HETATM across 85 apos: only `HG:4` (1N1M) and `VO4:1` (1YV3). Both left in apo; cognate titles are A3M and BIT respectively — residual detector correctly ignores non-cognate nonstd.
- Why it matters: Documents that “clean apo” ≠ “no HETATM at all”; ions/buffer can remain. Matches docking practice (keep metals when relevant).
- Fix recommendation: None required; optional note in CANONICAL that non-cognate HETATM are out of scope.
