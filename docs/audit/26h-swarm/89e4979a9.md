# Audit: 89e4979a9 — Add: Astex ligand-centered site PDBs for cognate-pocket redock

## Summary (2–4 sentences)

Commit `89e4979a950f1b9de9e738c8be1733df158d5f3c` freezes **20** `*_ligand_centered_site.pdb` files under the canonical Astex Diverse tree (`benchmarks/astex_diverse/astex_diverse/<PDB>/`). Each file is the **exact set of receptor ATOM/HETATM records within 6.0 Å of any cognate-ligand SDF atom** (Jaccard vs that shell ≈ 1.0 for all 20), with **byte-faithful crystal/apo coordinates** (serial + name + chain + resi + xyz match; max |Δ| = 0). These 20 IDs are **exactly** the Astex-85 subset whose legacy `*_binding_site.pdb` centroid lies **> 8 Å** from the ligand centroid — the same gate used by `write_ligand_centered_site()` / `prepare_astex` in `LIB/DatasetRunner.cpp` — so the freeze is a durable, checked-in repair for cognate-pocket redock, not a random 20/85 sample.

## Severity: LOW

Science data quality for the frozen sites is **high**. Residual issues are coverage/policy (65 targets still on GetCleft sites with ≤8 Å residual offset), three catalytic ions in the shell, and the fact that production still *prefers* `*_binding_site.pdb` unless the centroid gate trips.

## Findings

### F1. Site definition = cognate 6.0 Å atom shell of crystal ligand SDF (HIGH confidence / INFO–GOOD)

- Evidence: For every target, the set of LCS serials equals (or is a 1-atom superset of) `{ATOM/HETATM in crystal : min dist to any SDF ligand atom ≤ 6.0 Å}`:
  - **17/20**: Jaccard **1.000** vs the 6.0 Å shell (shell_only=0, site_only=0).
  - **1P62, 1R1H, 1YQY**: Jaccard **0.990–0.993** — each has **one extra HETATM** inside 6 Å (MG or ZN; see F5), not a wrong pocket.
  - `d_max` (site atom → nearest lig atom) ∈ **[5.88, 6.00] Å**; median site–lig distance ≈ **4.4–4.9 Å**.
  - Site centroid ↔ ligand centroid: mean **1.63 Å**, max **3.16 Å** (`1MQ6`); all ≪ the 8 Å repair gate.
- Match to engine: `write_ligand_centered_site` keeps any ATOM/HETATM line with \(d^2 \le 6^2\) to some SDF xyz (`LIB/DatasetRunner.cpp` ~1553–1588). Frozen files are consistent with that generator run against apo/complex protein atoms.
- Why it matters: Cognate-pocket redock is only “known site” if Ω is anchored on the **true ligand**, not a wrong GetCleft cavity. This definition is transparent, radius-stable, and ligand-SDF-driven (same frame as RMSD reference).
- Fix recommendation: None for geometry. Optional: document radius=6.0 and HETATM inclusion in `benchmarks/datasets/CANONICAL.md` next to the optional `*_ligand_centered_site.pdb` row.

### F2. Crystal / apo coordinate fidelity is perfect (GOOD)

- Evidence (n=20):
  - **100%** of LCS atoms match `{PDB}.pdb` by serial **and** (name, resn, chain, resi) **and** xyz (max coord Δ = **0.000 Å**).
  - **100%** also match `{PDB}_apo.pdb` by serial+xyz (ligand already stripped from apo; LCS contains **no** cognate ligand atoms).
  - Line prefix identity through coordinates vs crystal holds for all atoms.
- Why it matters: Oracle spheres built from corrupted/translated copies would silently shift LOCCLF / cleft grids and invalidate RMSD framing. These files are literal excerpts of the deposit/apo coordinate system.
- Fix recommendation: Keep LCS in the SHA256 manifest (already present; **20/20** hashes match `astex_diverse_sha256.csv` in this tree).

### F5. Full Astex-85 coverage of the >8 Å repair set is complete (GOOD)

- Evidence: Survey of all **85** targets with ligand SDF + binding_site:
  - **bc−lc > 8 Å: exactly 20** targets.
  - **All 20 have frozen LCS** in this commit.
  - **0** targets with bc−lc > 8 lack LCS.
  - **65** targets have bc−lc ≤ 8 Å (mean bc−lc over all 85 ≈ **5.9 Å**, median ≈ **5.0 Å**) and correctly have **no** LCS freeze (engine keeps GetCleft).
- Why it matters: Partial freezes of a repair policy create silent asymmetry (some IDs regenerated at runtime into cache, some committed). Here the freeze set **is** the full gate set.
- Fix recommendation: If operators want offline reproducibility without running DatasetRunner repair, ship only these 20 (done). Runtime may still rewrite LCS from apo+SDF when gate trips — content should match if radius stays 6.0.

### F6. Catalytic / structural ions in three sites (LOW)

- Evidence: HETATM inside LCS:
  - `1P62`: **MG** ×1  
  - `1R1H`: **ZN** ×1  
  - `1YQY`: **ZN** ×1  
  No cognate organic ligand atoms; no water-only sites.
- Why it matters: Generator includes **all** ATOM/HETATM within 6 Å of the ligand. Catalytic metals are often part of the true pocket chemistry; if the site file is only used as **sphere/centroid support** for LOCCLF (not as a typed receptor), impact is small. If any path treats site HETATM as movable or as full receptor atoms, ions need an explicit policy.
- Fix recommendation: Document “ions within 6 Å retained.” Optional filter to protein ATOM-only if LOCCLF ever mis-parses HETATM as ligand-like.

### F7. Atom-shell vs residue-complete pocket (INFO)

- Evidence: Best Jaccard of LCS vs “all atoms of residues with any atom ≤ R of ligand” peaks ~**0.48–0.78** (not 1.0). LCS is a **partial-atom** shell (sidechain-heavy contacts), not full residues. Residue-level recall@5 Å of near-ligand residues is still **1.0** (every contacted residue contributes ≥1 atom).
- Why it matters: Fine for centroid / sphere generation (many atoms still tile the pocket). Misleading if someone interprets LCS as a complete binding-residue list for pharmacophore or ΔS per-residue work.
- Fix recommendation: Name/docs: “ligand-centered **atom shell** (6 Å), not residue mask.”

### F8. Runtime policy still prefers GetCleft when ≤8 Å (INFO–LOW)

- Evidence: `prepare_astex` path sets `binding_site_path` from `*_binding_site.pdb` first; only if `delta > 8.0` does it write/use `*_ligand_centered_site.pdb` (`DatasetRunner.cpp` ~3909–3923). Committed LCS files are **not** an alternate primary for the 65 ≤8 Å cases.
- Why it matters: Residual GetCleft offsets of 5–8 Å can still bias the search volume on non-frozen IDs without tripping repair. This commit does not fix that band.
- Fix recommendation (out of band): Consider lowering the gate (e.g. 5 Å) or always preferring LCS when present; regenerate LCS for all 85 offline for a uniform cognate definition.

### F9. No tests / no generator script in this commit (LOW)

- Evidence: Pure PDB data; no unit test asserting shell radius, chain set, or SHA256 of LCS. Generator lives in parent engine commit, not here.
- Why it matters: Future hand-edits or re-exports could drift without CI.
- Fix recommendation: Add a pure-Python gate (similar to apo-strip validation): for each LCS, assert Jaccard vs 6 Å SDF shell ≥ 0.99 and site–lig centroid < 4 Å.

### F10. Security / hygiene (INFO)

- PDB atom records only; no secrets, no machine-absolute paths inside LCS bodies (unlike some GetCleft `#REMARK PARENTFILE /var/folders/...` lines on binding_site files). SHA256 rows already in repo manifest.
- Fix recommendation: N/A for LCS content.

### F11. CF / thermo / ranking language (INFO)

- Data commit only. Does not change CF scoring, TEMPER, FO MinPts, or election. Affects **where** the defined-cleft search is centered for 20 IDs when the repair path is active — can change which poses are found, not how CF ranks a fixed ensemble.
- Terminology: Still “cognate-pocket / defined-cleft redock,” not thermodynamic ΔG.
