## Findings

### F1. Constructor-only env snapshot can desync from live env and child engine (MEDIUM)
- Evidence: `DatasetRunner` ctor does `protocol_cfg_ = flexaids::ProtocolConfig::from_env()` once (`DatasetRunner.cpp` ~1887 at tip). All migrated call sites in `run()` read `protocol_cfg_`, not live `getenv`. Child FlexAID processes still re-read the same env names via `LIB/config_parser.cpp` (`FLEXAIDDS_N_ELITE`, `FLEXAIDDS_SHARING_ALPHA`, `FLEXAIDDS_VCT_ENTROPY_WEIGHT`, boom/sharing-related GA knobs) and residual `gaboom` getenv. `top.cpp` calls `from_env()` **twice** (hbond weight ~578; data_dir ~656) rather than one shared snapshot.
- Why it matters for science/repro: Long-lived runners or harnesses that `setenv` between construction and `run()`, or between parent dock_config emission and child spawn, can emit a dock_config whose echoed knobs disagree with what the engine actually applies from env. Audit greps of `dock_config.json` then lie relative to the real GA path. Documented residual in `docs/implementation/protocol-config.md` (“config_parser still applies …”) but not called out as a timing hazard.
- Fix recommendation: Resnapshot at `run()` entry (done in later chunk 2 / `c957d32b2` lineage — verify when auditing those commits). Prefer a single `ProtocolConfig` in `main`/`top.cpp` and pass by const-ref. Longer term: `apply_config(const ProtocolConfig*)` so engine and runner share one typed source (doc’s own chunk-2 recommendation).

### F2. Empty-string / invalid env semantics are not fully byte-identical to pre-migration getenv (LOW–MEDIUM)
- Evidence: Historical sites often treated **presence** of a non-null pointer as “set,” including empty `FLEXAIDDS_FOO=` and used `atoi`/`atof` (→ 0). Chunk-1 helpers tighten this:

  | Var | Old (parent `b056a1d3c`) | New (`from_env`) |
  |-----|--------------------------|------------------|
  | `RESTARTS=` (empty) | `max(1, atoi(""))` → **1** | `env_opt_int` nullopt → default **5** |
  | `SHARING_ALPHA=` | `atof("")` → **0.0** | nullopt → pop-scaled **4.0·pop_base/pop_scaled** |
  | `BOOM_FRAC=` | `atof("")` → **0.0** | nullopt → **1.0** |
  | `N_ELITE=` | `atoi("")` → **0** | nullopt → **1** |
  | `VCT_NORM=` / `USE_SHANNON=` / `THERMO=` empty | non-null → **ON** | `env_present` requires non-empty → **OFF** |
  | `HBOND_WEIGHT=` empty | `atof("")` → **0** | nullopt → **−2.5** |
  | Invalid float (`T_EFF=abc`) | `stof` could **throw** uncaught on thermo emission | `env_opt_double` → keep default |

  Well-formed overrides (`=3`, `=1`, `=0` on truthy-int gates) match tests and historical intent.
- Why it matters for science/repro: Production claim shells set explicit values, not empty exports — **default unset path is stable**. Empty-string edge cases are the only likely silent behavior flips; invalid floats are safer now (no throw).
- Fix recommendation: Document “empty means unset” as the contract in `protocol-config.md`. Optionally add unit cases for `""` and garbage numeric strings. Do **not** reintroduce divide-by-zero / throw paths for fidelity.

### F3. Dual-path residual: engine still owns several knobs DatasetRunner only echoes (LOW–MEDIUM)
- Evidence: Migrated DatasetRunner emission writes `n_elite`, `sharing_alpha`, VCT fields, Shannon flag, thermo block into per-restart `dock_config.json`. At the same tip, `config_parser.cpp` still does live getenv for `FLEXAIDDS_N_ELITE`, `FLEXAIDDS_SHARING_ALPHA`, `FLEXAIDDS_VCT_ENTROPY_WEIGHT`, etc. Residual inventory (~42 getenv sites in DatasetRunner/top/gaboom) is accurately documented.
- Why it matters for science/repro: Chunk 1 does **not** make ProtocolConfig the single source of truth for the GA engine. Operators changing only JSON (future skill path) without env still lose until chunks 2+. Claim campaigns that set env once remain consistent.
- Fix recommendation: Tracked residual — wire `apply_config` optional `const ProtocolConfig*` (already recommended in the doc). Do not claim “getenv free” after this merge alone.

### F4. `from_json` truncates `seed_base` through `as_int` (LOW)
- Evidence: `from_env` uses `std::stoull` → full `uint64_t`. `from_json` does `static_cast<std::uint64_t>(root["seed_base"].as_int(0))` where `json::Value::as_int` returns **`int`** (narrowing from stored `int64_t`). Large seed bases written by `to_json` can round-trip incorrectly. Unit test only uses `42` / `99`.
- Why it matters for science/repro: JSON protocol files / receipts with large `FLEXAIDDS_SEED_BASE` values would not restore the same deterministic seed stream. Env path is fine.
- Fix recommendation: Parse seed via `as_double`/`int64` helper or string; store as `uint64_t` without 32-bit `int` cast. Add round-trip test with `seed_base > INT_MAX`.

### F5. `to_json` / `from_json` incomplete provenance for audit ledger (LOW)
- Evidence: Chunk-1 JSON omits `parallel_restarts_explicit`. Optional fields round-trip when present; null sharing/boom encode correctly. `ProtocolConfig::to_json()` is **not** written into DatasetRunner dock_config or a RUN_RECEIPT in this PR (receipt arrives in later chunk 3). Tests cover defaults, a few overrides, presence/parallel edge, and partial JSON round-trip — not full field matrix, empty-string matrix, or DatasetRunner emission golden files.
- Why it matters for science/repro: Positive direction for serializable protocol knobs, but chunk 1 does not yet make runs self-describing on disk beyond existing dock_config echoes.
- Fix recommendation: Later chunks should embed `protocol_cfg_.to_json()` (or a stable subset) in RUN_RECEIPT / meta. Expand tests for every migrated field + `pop_scaled<=0` sharing-alpha guard.

### F6. Safety improvement: pop-scaled sharing alpha guards `pop_scaled <= 0` (INFO / positive)
- Evidence: Historical emission used bare `4.0 * pop_base / pop_scaled` (inf/UB if `pop_scaled==0`). `effective_sharing_alpha` returns `4.0` when `pop_scaled <= 0`. Invalid float env no longer throws on thermo emission path.
- Why it matters: Hardens dock_config emission without changing healthy DoF-scaled runs (`pop_scaled == pop_base` → 4.0 unchanged).
- Fix recommendation: Keep guard; optionally log when clamped.

### F7. CF / thermo language and ranking path (INFO)

Comments still correctly frame SMFREE / CF-scale behavior in DatasetRunner. `use_shannon` remains **presence** gate (even `=0` enables if set non-empty) — matches historical `if (getenv(...))`, not truthy-int; operators must unset to disable.
