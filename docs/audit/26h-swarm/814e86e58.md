## 3. Architecture of the harness

```
prepare_arm_AB.sh ──► generate_flexaid_inp.py
                          │
                          ▼
              $QUEUE/work/{A,B0,B}/<PDB>/
                 meta.json, CONFIG.inp, LIG.*, TARGET.*, spheres
                 restart_{0..R-1}/{CONFIG.inp,ga.inp,seed.txt}

run_{A,B0,B}_pilot8.sh ──► run_flexaid_arm_pilot8.sh <ARM>
                          │
                          ├─ preflight: binary, matrix MD5 pin, ProcessLigand
                          ├─ optional prepare (unless --no-prepare)
                          ├─ RUN_RECEIPT.json + provenance JSON
                          └─ for each PDB × restart:
                               caffeinate FlexAID CONFIG ga out_prefix
                               parse_flexaid_arm_results.py → result.csv
```

## 5. Defects & risks (as of `814e86e58`)

Severity: **P0** blocks correct pilot science; **P1** can contaminate claims or ops; **P2** hygiene / completeness.

### P0 — Missing `--legacy` on FlexAID invocation

```bash
# run_flexaid_arm_pilot8.sh @ merge
caffeinate -i -s "$BINARY" "$rdir/CONFIG.inp" "$rdir/ga.inp" "$prefix"
```

Staged A/B binaries are FlexAIDdS-unified CLI builds. Classic three-file CONFIG/ga mode requires **`--legacy`**. Without it, real pilot runs can fail or enter the wrong CLI path.  
**Evidence of impact:** fixed in later commit `5a24ebbd2` (“Staged A/B binaries need `--legacy` for classic CONFIG/ga”).  
**Smoke in the PR description may have used a binary/path that still accepted the 3-arg form**, masking the issue — do not treat PR smoke as proof that full pilot8 CLI is correct.

### P0 / P1 — Live I/O forced onto iCloud CloudDocs

```bash
case "$OUT" in
  *"/Mobile Documents/com~apple~CloudDocs/"*) ;;
  *) echo "REFUSE: output must be under iCloud Drive…"; exit 91 ;;
esac
```

Also defaults `FLEXAIDDS_RESULTS` to iCloud and writes work/logs under `$Q` which defaults to iCloud queue. This collides with the repository’s **local-first / thin-iCloud** production rule (AGENTS.md; later `ab0850a6d` / `5a24ebbd2`): live GA I/O on FileProvider paths hangs.  
At merge time the PR *intentionally* chose iCloud-only (and smoke verified iCloud OUT). That was **ops-risky** even if consistent with then-current “production on iCloud” docs (`f2fce514f` era). Grade as **ops P0 for long pilots**, design P1 for durability intent.

### P1 — Smoke contamination defenses are path-isolated but secondary checks are dead

`d7fc2afaa` correctly redirects smoke to `…/smoke/` so pilot8 OUT is not shared — **primary fix is good**.

Secondary refuse-skip logic is **ineffective**:

1. Checks `$odir/RUN_RECEIPT.json` (`OUT/<PDB>/…`) but receipt is written to **`$OUT/RUN_RECEIPT.json`** (campaign root), not per-PDB.
2. Checks `$odir/meta.json` for `"smoke": true`, but `meta.json` is written only under **work** (`$WORK_ROOT/$ARM/$pdb/meta.json`) and **never includes a smoke flag**.

If an operator ever forces smoke into pilot8 OUT via `FLEXAID_ARM_OUT`, skip logic will **not** refuse contamination.

### P1 — Arm B election is CF-only in the parser

For TEMPER 298 / FO clustering, protocol election should follow free-energy / BindingMode ranking when available. Parser always elects **lowest CF.app among rank-0 PDBs**. That is appropriate for **A and B0**, but **under-states or mis-states B’s thermo ranking** unless FlexAID’s rank-0 PDB is already free-energy ordered and CF.app is not the election key.

Also: `success_s2` / `pb_pass` empty → **cannot report protocol “success”** (RMSD≤2 **and** PoseBusters) from this CSV alone.

### P1 — Claim-eligibility flag is not a real gate

```python
"protocol_claim_eligible": 1 if args.matrix_md5 else 0,
```

Any non-empty matrix string (including the pin passed by the runner) marks eligible. No check that seed_echo was verified, PB passed, budget_class full, or smoke=false.

`budget_class` is hard-coded `"full"` even for smoke parses if someone points the parser at smoke OUT.

### P1 — Failures swallowed

- FlexAID non-zero exit → WARN, continue.
- `parse_flexaid_arm_results.py … || true`
- `run_one || true` in the target loop

Batch resilience is intentional, but a campaign can report **COMPLETE** with empty/partial PDBs and no non-zero process status. Operators must scrape logs.

### P2 — Machine-specific REPO fallback

```bash
if git -C "${HOME}/Projects/FlexAIDdS" rev-parse …; then
  REPO="$(git -C "${HOME}/Projects/FlexAIDdS" …)"
```

Violates spirit of AGENTS.md hygiene (“no machine-specific absolute paths in shared scripts”). Fallback to `dirname/..` exists, but the hard-coded Projects path is preferred when present — wrong on other machines that also have an old clone at that path.

### P2 — No automated tests

No pytest/unit coverage for generator CONFIG shapes, TEMPER/CLUSTA matrix, seed function, sphere rewrite, or parser REMARK extraction. Validation was manual smoke only (B0/1GPK tiny GA per PR body).

### P2 — ProcessLigand / OpenBabel env external

Hard dependency on `processligand-py` or `FLEXAIDDS_PROCESSLIGAND`. Documented; fine for ops, but prepare is non-hermetic.

### P2 — Absolute paths baked into CONFIG.inp

`write_config` resolves target/ligand/sphere/matrix to absolute paths. Work trees are not relocatable without regenerate. Acceptable for fixed queue roots; painful for local→iCloud sync of work.

### P2 — MAXRES default 10

Generator `maxres=10`. Later claim C0 work used MAXRES 50. Not necessarily wrong for classic FlexAID, but **unmatched** vs C0 if cross-arm MAXRES fairness is required — not documented in the harness.

### P2 — No DoF-aware pop scale for A/B

Protocol allows a budget ladder when FlexAID-2015 cannot hold 1000×6000. Harness always uses flat pop/gen. OK for pilot scaffolding; insufficient for matched eval budgets on high-DoF ligands.

## 9. Recommendations (for future work — not done here)

1. **Keep** the split: generator / shared runner / thin arm wrappers / parser — good modularity.
2. **Always** invoke FlexAID with `--legacy` for A/B0/B classic configs (already on tip via `5a24ebbd2`).
3. **Default** live OUT/work/logs to local APFS; thin-mirror `result.csv` + RUN_RECEIPT to iCloud (already direction of tip).
4. Fix smoke refuse-skip to read **parent** `OUT/RUN_RECEIPT.json` or write per-PDB receipts with `smoke` + `budget_class`.
5. Teach parser arm-aware election (CF for A/B0; free-energy fields for B when REMARKs/logs provide them) and wire optional PoseBusters for S2.
6. Make `protocol_claim_eligible` fail-closed (matrix pin match **and** non-smoke **and** seed flags **and** S2 when required).
7. Drop hard-coded `$HOME/Projects/FlexAIDdS`; resolve only via `FLEXAIDDS_ROOT` or script-relative root.
8. Add unit tests: seed stability, TEMPER/CLUSTA matrix, sphere HETATM rewrite, REMARK parse, smoke path isolation.
9. Propagate prepare failures and aggregate non-zero if any target failed when `STRICT=1`.
