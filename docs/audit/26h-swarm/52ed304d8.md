## Findings

### F1. Default `format_check.sh` fails on its own allowlist (MEDIUM)

- **Evidence:** With Homebrew `clang-format` 22.1.8 on PATH (`/opt/homebrew/opt/llvm/bin`), default allowlist run reports **DIFF on all 7** modern-module files and exits 1:
  - `LIB/statmech.cpp`, `statmech.h`, `encom.cpp`, `encom.h`
  - `LIB/UnifiedHardwareDispatch.h`, `LIB/VoronoiCFBatch.h`
  - `python/bindings/core_bindings.cpp`
- **Why it matters:** CONTRIBUTING and PR body present `scripts/format_check.sh` as the safe PR check. Wiring it into CI **as-is** would red-gate every PR without any functional change. Codex PR review already flagged the same P2 (“keep default format check passing”).
- **Fix recommendation:** Either (a) intentionally format the allowlist in a dedicated style-only PR, or (b) start with an empty / narrower allowlist of files already clean under `.clang-format`, or (c) document “advisory until green” and keep CI off until `format_check: PASS`. Do **not** mass-format all of `LIB/`.

### F2. Optional pre-commit clang-format can rewrite entire staged legacy TUs (MEDIUM)

- **Evidence:** `.pre-commit-config.yaml` registers `mirrors-clang-format` v19.1.7 on all `c++/c/cuda` except `LIB/third_party/`, `.tools/`, `build.*/`. That hook **rewrites** staged files (`clang-format -i` style), not dry-run. Staging a one-line fix in `gaboom.cpp` / `Vcontacts.cpp` would reformat the whole file under LLVM Attach / 4-space rules while the tree is still largely tabs + Allman.
- **Also:** `minimum_pre_commit_version: '3.0.0'` while `default_stages: [pre-commit]` needs pre-commit ≥ 3.2.0 for that stage spelling (Codex P2). Hook pin is clang-format **19**; local Homebrew may be **22** — style drift between contributors is likely.
- **Why it matters:** Silent style bombs in functional PRs violate the PR’s own “no mass reformat” contract and explode review noise.
- **Fix recommendation:** Exclude `LIB/` legacy globs (or require files match `format_check` allowlist); prefer `scripts/format_check.sh` dry-run hook; raise `minimum_pre_commit_version` to `3.2.0+`; pin / document one clang-format major for contributors.

### F3. YAML `canonical_*` keys are documentation theater (LOW–MEDIUM)

- **Evidence:** Both dataset YAMLs add:
  ```yaml
  canonical_data_root: benchmarks/astex_diverse/astex_diverse
  checksum_manifest: benchmarks/datasets/astex_diverse_sha256.csv
  canonical_doc: benchmarks/datasets/CANONICAL.md
  ```
  `DatasetConfig.from_yaml` (`python/flexaidds/dataset_runner/runner.py`) only `pop`s known fields and **drops** these keys; no C++ path resolver reads them. Runtime structures still come from cache (`~/.flexaidds/benchmarks/…`), downloads, and `FLEXAIDDS_ORACLE_SITE_DIR` — as CANONICAL.md itself states.
- **Why it matters:** Agents/operators may assume YAML now **enforces** the canonical tree. Path wrongness is still a human/env mistake. CodeRabbit noted the same “wire schema or mark docs-only.”
- **Fix recommendation:** Prefix keys with `x_` / put under `docs:` / comment `# docs-only`, **or** plumb `canonical_data_root` into prepare/oracle fallback and a checksum gate. Keep dual YAML copies in lockstep (this PR does).

### F4. “Canonical apo” files are mostly byte-identical to deposit PDBs (MEDIUM — data quality, not introduced by code)

- **Evidence (current tree + committed CSV, verified this session):**
  - `python3 scripts/generate_astex_manifest.py --check` → **OK** (445 files, 85 targets).
  - **83/85** pairs `{id}.pdb` / `{id}_apo.pdb` share the **same SHA256**.
  - Only **1TW6** and **2BYS** differ (2BYS apo ~270 KiB vs holo ~1.3 MiB).
  - Spot HETATM counts: e.g. `1G9V` apo and holo both have **172** HETATM lines; many “apo” files still contain waters/cofactors/ligands depending on prep.
  - Nested `data/astex_diverse` **differs** on apo/PDB hashes; ligands often match; many lack `_binding_site.pdb` — matches CANONICAL.md narrative.
- **Why it matters for science/repro:** CANONICAL.md correctly deprecates the nested tree and pins **which files** are authoritative, which is valuable. It does **not** assert that `_apo.pdb` means “cognate ligand removed.” Labeling the tree “apo” while 83/85 are holo-identical can bias self-docking claims if a runner trusts the filename without stripping. Production claim paths that re-prepare via `prepare_pdb_entry` / cache may not even use these apo blobs as-is — but ORACLE_SITE and hand scripts often do.
- **Fix recommendation:** Follow-up data PR: regenerate true apo (ligand HETATM removed, waters policy documented), rehash CSV+JSON in the same PR, and add a gate (e.g. fail if apo SHA == holo SHA unless allowlisted). Until then, claim prose should say “repo structure tree” not “validated apo receptors.”

### F5. Manifest `--check` is incomplete / soft (LOW–MEDIUM)

- **Evidence:**
  - `--check` compares **CSV text only**; regenerates `json_text` but never compares `astex_diverse_manifest.json` (stale target list or suffix list can drift while CSV check passes). CodeRabbit asked to compare JSON ignoring `generated_utc`.
  - Missing key files are **skipped** in `collect()`; a truncated tree can still produce a matching CSV if the CSV was regenerated from that incomplete tree. Codex verified pass with a one-file fake tree.
  - No CI job runs `generate_astex_manifest.py --check` or `format_check.sh` (grep of `.github/` empty for these names at audit time).
- **Why it matters:** Manifests look like hard reproducibility pins; they are **opt-in operator tools** without fail-closed completeness.
- **Fix recommendation:** Require at least `{id}_apo.pdb`, `{id}_ligand.sdf`, `{id}_binding_site.pdb` for every directory under the canonical root; fail if `n_targets != 85` or any required suffix missing; check JSON minus timestamp; add a cheap CI step (Python only, no clang-format dependency).
