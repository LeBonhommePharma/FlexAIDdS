# Audit: 26cb99276 — Fix: oracle-ceiling native pose seed when reference_ligand.file is set

**Commit:** `26cb9927638e18c72e3aba0b1fcd43783fe5d526`

**Scope of this audit:** scientific contamination risk (fair claim redock), gate defaults, test coverage. **No source edits.**

## Summary (2–4 sentences)

This commit repairs **oracle / native-inheritance** gen-0 seeding so that `pose_seed_enabled` + `seed_fraction>0` injects crystal IC (`gene0=0` + `opt_par` orientations/torsions) even when `reference_ligand.file` is non-empty. That matches the then-current DatasetRunner contract (RMSD crystal SDF always written into `reference_ligand.file`; oracle mode used `seed_fraction=0.90`). **Fair claim redock paths that already set `seed_fraction=0` and `pose_seed_enabled=false` are not activated by this gate** (`seed_budget=0` ⇒ no flood). Residual risk is the **unsafe engine defaults** (`pose_seed_enabled=true`, `seed_fraction=0.25`) plus a **broader activation condition** (no longer requires `reflig_nearest_count>0`), and **zero automated tests** of the new gate.

## Severity: HIGH (for seeded / default paths); LOW for properly gated claim emission

Critical question answers up front:

| Question | Answer |
|----------|--------|
| Does oracle seed contaminate **fair claim** redock? | **No**, when claim configs keep `seed_fraction=0` **and** `pose_seed_enabled=false` (DatasetRunner AUTONOMOUS / DEFINED_CLEFT at this commit; all modes after `dea70ea88`). |
| Gate default? | **Unsafe for blind science:** defaults are `pose_seed_enabled=true`, `seed_fraction=0.25`. Claim safety is a **caller / DatasetRunner emission** property, not a fail-closed engine default. |
| Test coverage? | **Inadequate.** No gtest/pytest for `want_pose_seed`, `[REFLIG-SEED]`, or “file set ⇒ still seed”. Only parser/nearest-grid unit tests elsewhere. Smoke 1GPK is commit-message only. |

## What the commit changes (mechanics)

### A. RefLig / native pose seed rewrite (`populate_chromosomes`)

**Before (parent):**

```cpp
const bool reflig_seeded =
    FA->reflig_nearest_count > 0 &&
    i < popoffset + seed_budget;

bool native_direct_seed =
    FA->reflig_file[0] == '\0' && FA->reflig_hetatm_fallback &&
    FA->resligand != NULL && gene_lim[0].min <= 0.0;
// orientations only if typ == 1 || typ == 2
```

**After:**

```cpp
const bool want_pose_seed =
    FA->reflig_pose_seed_enabled &&
    FA->opt_par != nullptr &&
    FA->map_par != nullptr &&
    seed_budget > 0;
const bool reflig_seeded =
    (FA->reflig_nearest_count > 0 || want_pose_seed) &&
    i < popoffset + seed_budget;
const bool native_direct_seed =
    FA->resligand != NULL && gene_lim[0].min <= 0.0 &&
    (FA->reflig_file[0] == '\0' || FA->reflig_pose_seed_enabled);
// copy ALL genes g≥1 except typ==3; ±0.5° jitter on typ 1|2 for i>popoffset
// log [REFLIG-SEED] once for first seeded individual
```

**Scientific intent (valid):** DatasetRunner at parent **always** put the crystal SDF path into `reference_ligand.file` for RMSD/PoseBusters. That forced `native_direct_seed=false` (required empty file), and seeding itself required `reflig_nearest_count>0`. Live oracle runs could keep **random orientations** in the “seeded” budget despite `seed_fraction=0.9` (commit cites Astex 1GPK gen-0 CF≈+32 vs hist native flood CF≈−74). Fix restores gene0 anchor 0 + `opt_par` flood when pose seed is on.

### B. Coarse-init ring randomisation removed after injection

After coarse seeds are written into gen-0, **parent** called `ring_randomise_chrom` on those chromosomes (mutating genes after score acceptance). **This commit** skips that for the coarse-init block so screened genes match scored seeds. Residual population still ring-randomises later. Good for autonomous/coarse_init fidelity; orthogonal to oracle flood but same function.

### C. Dirty-atom bounds for selective copy

`calculate_fitness` / parallel dirty lists skip `map_par[].atm` / `mov[]` indices outside `[1,natm]` (pseudo indices ≥90000). Defensive OOB fix for direct-mode rigid-body params — not a seed gate, but reduces silent memory corruption risk when scoring seeded / direct-mode chromosomes.

## Findings

### F1. Fair claim redock is gated off by `seed_budget`, not by empty file (CRITICAL clarifying finding — PASS for claim emission)

**Evidence (parent DatasetRunner emission, contemporaneous with this commit):**

```text
"reference_ligand": {
  "file": <rmsd_reference_path if exists>,   // ALWAYS set when RMSD ref exists
  "seed_fraction":  0.0  if AUTONOMOUS || DEFINED_CLEFT_REDOCK else 0.90,
  "pose_seed_enabled": false if AUTONOMOUS || DEFINED_CLEFT_REDOCK else true,
}
```

With `seed_fraction=0`:

- `seed_budget = int(0 * pop) = 0`
- `want_pose_seed = … && seed_budget > 0` → **false**
- `reflig_seeded = (…) && i < popoffset + 0` → **false** for all residual chromosomes

Therefore this commit **cannot** inject native orientation flood into AUTONOMOUS or DEFINED_CLEFT_REDOCK runs that honor DatasetRunner’s emission, even though `file` is non-empty.

**Also at parent:** `result.native_pose_seeded = (mode ∉ {AUTONOMOUS, DEFINED_CLEFT_REDOCK})`, so ORACLE_CEILING rows are **claim-ineligible** (`protocol_claim_eligible` requires `!native_pose_seeded && !seed_echo`). Admission contract (`seed_echo==0`, `native_pose_seeded==0`) would reject oracle rows if mixed into claim aggregates.

**Why it matters:** The critical contamination question is about **fair claim**, not oracle ceiling. Contaminating oracle is the *purpose* of the fix. Claim isolation depends on **seed knobs**, which DatasetRunner already zeroed for claim modes.

**Fix recommendation:** Keep claim emission fail-closed (`seed_fraction=0`, `pose_seed_enabled=false`, prefer empty `file` + separate `rmsd_reference` / `FLEXAIDDS_RMSDST` as in later `dea70ea88`). Never rely on “file empty” as the anti-leak gate — this commit deliberately decoupled that.

### F2. Engine defaults remain answer-leaking (HIGH)

**Evidence:**

| Source | `seed_fraction` | `pose_seed_enabled` |
|--------|-----------------|---------------------|
| `LIB/config_defaults.h` | **0.25** | **true** |
| `LIB/config_parser.cpp` jflt/jbool fallbacks | 0.25 / true | (same) |
| `LIB/top.cpp` FA init | 0.25 | **not set** (zero until apply_config) |
| Claim DatasetRunner (parent) | 0.0 | false |
| Oracle DatasetRunner (parent) | 0.90 | true |
| DatasetRunner HEAD (`dea70ea88`+) | 0.0 / empty file / false for **all** modes |

`load_config` merges `flexaid_default_config()` under user JSON. Any config that **omits** `reference_ligand` inherits seed 0.25 + pose true.

**Behavior change from this commit under defaults:**

| | Parent | After 26cb99276 |
|--|--------|-----------------|
| Activation | needs `reflig_nearest_count > 0` | `want_pose_seed` **OR** nearest |
| Empty file + defaults, nearest=0 | **no** RefLig flood | **yes** ~25% gene0=0 + `opt_par` flood |

So the commit **widens** default-path native inheritance: nearest-grid prep is no longer a prerequisite. For unblinded cognate inputs, `opt_par` is the input/crystal IC frame → systematic gen-0 answer bias.

**Why it matters:** Fair claim is safe only when **orchestration** overrides defaults. Direct CLI / partial JSON / forgotten knobs now leak more easily than before. Violates “fail closed” scientific hygiene for blind docking.

**Fix recommendation (not done in this audit):** Flip defaults to `pose_seed_enabled=false`, `seed_fraction=0.0`. Require explicit opt-in for oracle-ceiling restore campaigns. Clamp `seed_fraction` to [0,1]. Optionally refuse `pose_seed_enabled && seed_fraction>0` unless an explicit `mode=oracle` / env `FLEXAIDDS_ALLOW_NATIVE_SEED=1` is set.

### F3. `native_direct_seed` no longer requires `hetatm_fallback`; file non-empty + pose_seed ⇒ gene0=0 (MEDIUM)

**Before:** empty file **and** `hetatm_fallback` **and** resligand **and** gene0 min≤0.  
**After:** resligand **and** gene0 min≤0 **and** (empty file **OR** `pose_seed_enabled`).

With oracle emission (`pose_seed_enabled=true`, file set), gene0 is forced to **grid index 0** (native anchor), not K-nearest cycle. That is correct for crystal IC inheritance but **stronger** than nearest-grid bias alone.

**Why it matters:** Grid index 0 is defined as the reference conformation slot in site confinement (`top.cpp` SITE-CONFINE preserves i=0). Flooding 90% of gen-0 onto that anchor + full `opt_par` is true native pose inheritance — not “site-aware random search.”

**Fix recommendation:** Document that `pose_seed_enabled` means **pose inheritance**, not pocket prior. Keep oracle aggregator (`scripts/aggregate_oracle_ceiling.py`) separate from claim metrics (already protocol policy).

---

### F4. Orientation copy scope expanded: all genes except typ==3 (MEDIUM)

**Before:** only `typ == 1` (angle) and `typ == 2` (dihedral).  
**After:** skip only `typ == 3` (normal modes); also copies typ 4 (rotamers) and any other gene types from `opt_par`.

Tiny jitter (±0.5°, dice%5) applies only to typ 1|2 for clones after the first seeded individual.

**Why it matters:** Broader native copy increases basin fidelity for oracle ceiling (desired) and increases answer leakage if the gate is ever mis-set on claim. Rotamer genes at crystal values can also bias flexible-receptor redock.

**Fix recommendation:** If claim ever needs “translation-only” pocket prior without pose inheritance, keep a separate knob (nearest-grid / MIF) with `pose_seed_enabled=false` — which still allows gene0 nearest bias when `seed_budget>0 && nearest_count>0`.

### F6. Naming / protocol drift: “oracle-ceiling” means different things over time (MEDIUM)

**At this commit (2026-07-14 morning):** DatasetRunner `ORACLE_CEILING` ⇒ `seed_fraction=0.90`, `pose_seed_enabled=true`, no ligand blinding when site present, `native_pose_seeded=true`.

**Same day later (`dea70ea88` ~17:03):** no-seed cognate stack — DatasetRunner emits empty `file`, `seed_fraction=0`, `pose_seed_enabled=false` even for known-site modes; RMSD via `rmsd_reference_path` / `FLEXAIDDS_RMSDST`.

**HEAD protocol** (`three_engine_entropy_comparison.md`, admission contract): native pose seed **forbidden** on claim; “oracle-ceiling” often means pocket-confined / fixed-budget **without** inheritance; seeded track is separate (`aggregate_oracle_ceiling.py`).

**Why it matters:** Reading this commit’s subject against HEAD protocol can invert meaning (“oracle-ceiling” as fair redock vs native seed ceiling). Hist v43 “no file” vs “file set” confusion is exactly the bug class this fix addresses — and why dual use of `reference_ligand.file` for RMSD **and** seeding was a design error.

**Fix recommendation:** Keep terminology: **seeded oracle ceiling** vs **defined-cleft / no-seed redock**. Never mix rates. Grep claim logs for `[REFLIG-SEED]` and fail admission if present.

### F7. Secondary paths and residual leakage (LOW–MEDIUM)

1. **Legacy `.ga` `REFLGSED`** re-parses `reflig_seed_fraction` after JSON (`gaboom.cpp` ~3552) and can override claim-safe JSON — pre-existing reproducibility hazard (also noted in `flexaidds_methodology_audit.md`).
2. **`coarse_init.cpp`** forces `FA->reflig_seed_fraction = 0.0f` during coarse scan so native flood cannot wipe coarse seeds — mitigates autonomous path if seed fraction were accidentally >0 **only after** coarse_init runs; not a substitute for correct config.
3. **`ParallelDock.cpp`** zeros `reflig_seed_fraction` on worker FA — subgrid safety, not claim protocol.
4. **Admission `native_pose_seeded` is mode-based**, not parsed from actual JSON seed knobs. If a hand-edited config enables seed under AUTONOMOUS emission path without changing mode, flags could lie. (DatasetRunner emission is the real control; mode flag is secondary.)
5. **`seed_fraction` unclamped** — values >1 over-seed silently (pre-existing).

## Critical question: contamination of fair claim redock?

### Direct answer

**Does this commit make fair claim redock inherit the crystal pose?**

- **DatasetRunner AUTONOMOUS / DEFINED_CLEFT_REDOCK at commit time: No.** Emission forces `seed_fraction=0` and `pose_seed_enabled=false` ⇒ `want_pose_seed=false` and empty seed budget. Setting `reference_ligand.file` for RMSD alone does **not** enable the flood after this fix (because seed knobs are still zero).
- **DatasetRunner ORACLE_CEILING at commit time: Yes, by design** (and previously intended but broken when file was set). Flagged `native_pose_seeded=1`, not claim-eligible.
- **Default / incomplete configs without explicit zeroing: Increased risk after this commit** (F2) — nearest-grid no longer required for pose flood.
- **HEAD DatasetRunner (post-`dea70ea88`): All modes emit seed off + empty file.** Oracle seed only if operators **manually** re-enable knobs (smoke JSON, custom restore). This commit’s code remains the mechanism those knobs call.

### Gate matrix (post-commit)

| `pose_seed_enabled` | `seed_fraction` | `file` | Nearest>0 | Gen-0 native IC flood? |
|---------------------|-----------------|--------|-----------|-------------------------|
| false | 0 | any | any | **No** (claim path) |
| false | >0 | any | yes | gene0 nearest only, **no** opt_par flood |
| true | 0 | any | any | **No** (`seed_budget=0`) |
| true | >0 | empty | no | **Yes** (gene0=0 + opt_par) — **new** vs parent |
| true | >0 | set | any | **Yes** (gene0=0 + opt_par) — **fixed oracle** |
| true | 0.9 | set | — | Oracle ceiling (parent DatasetRunner) |

**Default gate (`true` / `0.25`) is not fail-closed for blind science.** Claim safety is orchestration-level.
