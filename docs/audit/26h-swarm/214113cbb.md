## Findings

### F1. Floating major tag `@v6` vs SHA-pin discipline elsewhere (LOW–MEDIUM, supply chain)
- Evidence: Same workflows pin peers by commit SHA with version comments, e.g. `actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v6`, `actions/setup-python@a309ff8b… # v6`, `actions/upload-artifact@043fb46d… # v7`, `marocchino/sticky-pull-request-comment@5770ad5e… # v3.0.5`. Dependabot only rewrote the **mutable** tag:
  ```yaml
  uses: actions/cache@v6
  ```
  Floating majors move when GitHub retags `v6` (any future 6.x). Dependabot’s own PR tip at merge time pointed at the then-current v6 line (includes readonly-token fix commits in compare `v4...v6`); the **tree does not pin that commit**.
- Why it matters: Cache steps restore **build/** (compiled FlexAID) and intended benchmark datasets. A compromised or buggy retag could poison restore contents; subsequent steps trust `cache-hit` and **skip rebuild**, so a bad hit is more dangerous than a miss. AGENTS.md hygiene does not ban floating Actions tags, but the rest of these files already practice pin-by-SHA.
- Fix recommendation: Follow peer style — `uses: actions/cache@<full-sha> # v6.x.y` (or Dependabot `commit-message` / versioning strategy that pins SHAs). Prefer exact minor (`@v6.1.0`) only if org policy forbids SHAs; SHA is stronger.

### F2. Major jump inherits Node 24 / runner floor from v5 (LOW; INFO on current runners)
- Evidence: RELEASES.md v5.0.0: *“runs on the Node.js 24 runtime and requires a minimum Actions Runner version of 2.327.1.”* Both workflows use `runs-on: ubuntu-latest` (GitHub-hosted; current images satisfy this). `benchmark-mpi` job is `if: false` with a comment to switch to self-hosted later; it does **not** call `actions/cache` today. `metal-self-hosted.yml` also has no `actions/cache` usage.
- Why it matters: If someone later copies the tier2 cache pattern onto an **old** self-hosted runner without upgrading, cache steps fail closed (job error), not silent wrong science. No current production path is blocked.
- Fix recommendation: Document runner ≥ 2.327.1 next to any future self-hosted enablement of these caches. No change required for ubuntu-latest.

### F3. PR merged with zero reviews; mixed status checks (LOW process)
- Evidence: `gh pr view 252` → `"reviews": []`. Status rollup on the PR included **SUCCESS** for the workflow that actually exercises this action (`Tier-1 Benchmark (casf2016)` under “Benchmark Tier 1 (PR Sanity)”), plus SUCCESS CodeQL / License scan, but also **FAILURE** on unrelated jobs (`Coverage Analysis (Linux/Clang)`, `Pure Python results tests`) that do not touch `actions/cache`.
- Why it matters: Merge discipline for Dependabot majors is weak if red checks are ignored without triage. Here the **relevant** check (tier1 cache path) passed; failures appear orthogonal to the 6-line YAML bump. Still: “all green or explicit waiver” is better than silent merge on mixed rollup.
- Fix recommendation: For Actions majors, require green on workflows that use the action; document waiver of unrelated red jobs. Optional: branch protection requiring tier1 + license-scan for `.github/workflows/**`.

### F4. Build cache key under-hashes build inputs (pre-existing; not introduced) (LOW)
- Evidence: Key hashes only `CMakeLists.txt` + `LIB/**/*.cpp` + `LIB/**/*.h`. Cache `path: build` includes Ninja outputs. Unhashed factors that can change binary behavior without key rotation: CMake flags in the workflow (`FLEXAIDS_USE_*`, `BUILD_TESTING`, compiler `gcc-14`), `cmake/` modules, Metal/OBJCXX bridges if ever enabled, non-`LIB/` sources linked into FlexAID, and OS image drift under `runner.os` alone.
- Why it matters for science/repro: Tier1/tier2 CI may **reuse** a stale FlexAID binary after a flag-only workflow edit until LIB/CMakeLists touch. That can mask or invent benchmark regressions in **CI** only. Local claim campaigns (AGENTS.md local-first OUT) do not use these caches.
- Fix recommendation (follow-up, not this commit’s fault): Extend `hashFiles` to the workflow file itself and/or a pinned `CI_CACHE_BUST` env, and/or hash `cmake/**` + relevant non-LIB sources. Consider caching `ccache` or dependency packages instead of the entire `build/` tree.

### F5. Dataset caches are inert scaffolding today (pre-existing INFO)
- Evidence: Tier2 download step maps empty `ZENODO_RECORDS = {}` with commented placeholders; prints *“Zenodo download not yet configured”*. Push events force `DRY_RUN_FLAG` dry-run. Caching empty/missing `benchmark_data/*` directories is harmless but does not accelerate real CASF/ITC/DUD-E/MUV materialization until Zenodo IDs land.
- Why it matters: Bumping cache action version on dead paths has no operational benefit yet; also no new risk of serving wrong scientific datasets in CI until downloads exist.
- Fix recommendation: When Zenodo IDs are registered, bump cache key suffix (`…-v2`) on any dataset content change; keep action SHA-pinned.

### F6. No ranking, CF proxy, DoF budget, or thermodynamic path change (INFO)
- Evidence: Diff is exclusively `.github/workflows/*.yml` action refs. No touch to `LIB/gaboom.cpp`, `Vcontacts`, `statmech`, `BindingMode`, `DatasetRunner`, claim scripts, or YAML dataset semantics.
- Why it matters: AGENTS.md scientific guardrails (CF vs ΔG language, pop-not-gen budget, ranking preservation) are out of scope for this merge.
- Fix recommendation: N/A.

### F7. Security positives of the bump (INFO / mild positive)
- Evidence: Moving off floating v4 to v6 pulls intermediate fixes (e.g. SAS token obfuscation in debug logs v4.2.3, cache backend v2 alignment, v5.x dependency CVEs). Action remains official `actions/*` namespace.
- Residual: Floating tag (F1) still means automatic pickup of future 6.x without review — double-edged.
- Fix recommendation: Pin SHA to lock both security baseline and surprise.
