### F2. Stated naming fix is correct and aligns with AGENTS.md (HIGH value, PASS)

- **Evidence — before (pre-gut full header language, e.g. `dea70ea88`):**
  ```cpp
  float best_score{0.0f};           // FlexAIDdS free energy (kcal/mol)
  float predicted_dG{0.0f};         // predicted ΔG (kcal/mol)
  ```
- **Evidence — after (merge tip):**
  ```cpp
  ///   - best_score  ≡ CF/contact-function scoring proxy … NOT ΔG.
  ///   - predicted_dG ≡ ensemble-derived free-energy *estimate* F …
  ///                   … NOT experimental binding free energy …
  float best_score{0.0f};  // documented as CF proxy; CSV name historical
  float predicted_dG{0.0f}; // F estimate or CF fallback — not exp. ΔG
  ```
- **Assignment sites (behavior unchanged):**
  ```cpp
  result.best_score = best_cf;  // CF proxy; column name is historical
  result.predicted_dG = have_free_energy ? free_energy_F
                      : (best_dG != 0.0f) ? best_dG
                                          : best_cf;
  ```
- **Human report labels (string-only product change):** markdown table headers go from `Score` / `ΔG` / `ΔH` / `TΔS` to `CF (best_score)` / `F_est (predicted_dG)` / `ΔH_est` / `TΔS_est` with an explicit column-notes paragraph. Cross-ligand section: “Ranked Ligands (by ensemble F estimate…)” instead of “by ΔG”.
- **Why it matters:** AGENTS.md requires separating the **CF/contact-function scoring proxy** from true thermodynamic free-energy claims. The old field comment (`// FlexAIDdS free energy`) was actively dangerous for agents, PR prose, and paper drafts that scrape headers. This PR is the right fix for the DatasetRunner schema surface.
- **Fix recommendation:** Keep the contract; prefer `cf_score` / `F_est` language in **new** docs and logs; do not rename CSV columns without a coordinated migration (PR correctly left headers stable).

### F5. Residual dangerous names remain by design (MEDIUM — residual debt)

| Location | Residual | Risk |
|----------|----------|------|
| CSV column `best_score` | Historical name | Agents map “score” → energy without reading docs |
| CSV column `predicted_dG` | Historical name | Strong “ΔG” connotation; may be **CF fallback** |
| Cross-ligand CSV `delta_G_kcal` | Header unchanged; comment says F_est | Same |
| `LIB/GrandPartitionFunction.h` | `double dG`, `rank()` “by ΔG” | Grand-PF session energy still labeled ΔG in API |
| `LIB/TargetServer.h` | “Rank all ligands by ΔG” | Same |
| `DockingResult::thermo_G_bind` | Field name `G_bind` | Distinct thermo path; still “G” language |
| Affinity correlation | `pred_affinities.push_back(-r.predicted_dG / 1.3636)` | Converts column to pKd even when value is **CF** |

- **Evidence (affinity path, unchanged by this PR):**
  ```cpp
  if (entries[i].has_affinity() && r.predicted_dG != 0.0f) {
      exp_affinities.push_back(entries[i].experimental_affinity);
      pred_affinities.push_back(-r.predicted_dG / 1.3636); // convert to pKd
  }
  ```
  When `have_free_energy` is false, `predicted_dG` is CF (or `best_dG` parse). Treating CF as kcal/mol ΔG for pKd is a **scientific misuse** that this naming PR documents but does not gate.
- **Why it matters:** Naming clarity without a `predicted_dG_source` provenance flag still allows Pearson-r / affinity plots to be misread as free-energy calibration.
- **Fix recommendation (P1 science hygiene):**
  1. Add CSV columns `best_score_kind=cf` and `predicted_dG_kind=ensemble_F|cf_fallback|parsed_dG` (additive; keep old headers).
  2. Skip affinity pairs when kind ≠ ensemble_F (or gate behind explicit env).
  3. Rename grand-PF `dG` → `F_est` in API over a deprecation window; update TargetServer docs.
