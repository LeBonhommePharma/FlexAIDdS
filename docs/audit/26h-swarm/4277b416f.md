## 4. Engine contract cross-check (not modified by commit; validates knobs)

### 4.1 `FLEXAIDDS_EVAL_SCALE_DIHEDRAL=1` → pop×DoF, gen fixed

`LIB/DatasetRunner.cpp` (current contract, matching AGENTS.md):

- mode **1**: `pop_effective = pop_base × max(1, n_flex_bonds/4)`; **`n_gen` stays at base**
- mode **0**: legacy **generation** scale — forbidden for claim
- mode **−1**: fixed pop+gen — oracle-ceiling only

C0 launcher correctly selects mode **1** and freezes base gen at **2000**.

### 4.2 `FLEXAIDDS_BUDGET_SCALE=1`

When `n_genes ≥ 14`: extra **population** multiplier `× max(1, n_genes/7)`; generations still fixed. C0 enables this.

### 4.3 `kBenchmarkPoseLimit = 50`

DatasetRunner writes `"output": { "max_results": 50 }` and enumerates poses with that ceiling. Aligns with generator `MAXRES 50` for FlexAID S3/BCR comparability.

### 4.4 TEMPER 21 semantics (not Kelvin room temperature)

`LIB/read_input.cpp` documents: for FlexAID, `TEMPER` is an **effective softmax temperature over the unitless CF landscape**, with `β = 1/T` — **not** physical kT in kcal/mol (3Dsig 2017).  

- T=21 → colder soft-max (sharper mode weighting) than T=298.  
- T=0 → forces CF clustering (arm B0).  
- FlexAIDdS C0 still uses physical **298 K** for thermo ledger paths — correctly separated in this freeze.

### 4.5 Default engine MAXRES without generator

Classic defaults remain `max_results=10` in `config_defaults.h` / `top.cpp`. **Only** generated three-engine FlexAID configs and DatasetRunner JSON raise the ceiling to 50. Stale hand-written INPs stay at 10.

**Positive**

1. Reboots C0 off a **dirty residual** (`EVAL_SCALE=-1` frozen budget) onto normative **pop×DoF**.  
2. Restores **3Dsig base depth** (2e6) after an earlier protocol draft that used gen=6000 (base 6e6).

**Risks**
