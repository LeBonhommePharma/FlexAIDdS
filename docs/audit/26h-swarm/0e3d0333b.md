## Focus A — shell_exec argv hashing

### A1 — Resolution keeps main’s hardened path (PASS)

Merged `DatasetRunner::run()` receipt block (`LIB/DatasetRunner.cpp` ~5071–5136):

```cpp
// Argv-only hash helpers — no shell (security harden from main).
auto md5_of = [](const std::string& path) -> std::string {
    if (path.empty() || !fs::exists(path) || !is_safe_exec_path(path)) return "";
    std::string t = run_argv_first_token({"md5", "-q", path});
    if (t.empty()) t = run_argv_first_token({"md5sum", path});
    return t;
};
auto sha256_of = [](const std::string& path) -> std::string {
    if (path.empty() || !fs::exists(path) || !is_safe_exec_path(path)) return "";
    std::string t = flexaids::posebust::sha256_file(path);
    if (t.empty()) t = run_argv_first_token({"shasum", "-a", "256", path});
    if (t.empty()) t = run_argv_first_token({"sha256sum", path});
    return t;
};
// ...
receipt.git_commit = run_argv_first_token({"git", "rev-parse", "HEAD"});
```

**What was correctly discarded from #277:**

```cpp
// PR #277 (NOT in merge result) — shell injection surface on paths
auto cmd_token = [](const std::string& cmd) -> std::string {
    FILE* p = popen(cmd.c_str(), "r");  // ...
};
auto md5_of = [&](const std::string& path) {
    std::string t = cmd_token("md5 -q " + shell_quote(path) + " 2>/dev/null");
    // ...
};
```

Even with `shell_quote`, routing untrusted paths through `popen`/`sh -c` is the anti-pattern that `LIB/shell_exec.h` and PRs #275/`4dabec565` eliminated. Merge resolution is **correct and required**.

### A2 — `shell_exec` contract (context)

`LIB/shell_exec.h` (header-only, already on main before this merge):

| Helper | Behavior |
|--------|----------|
| `validate_exec_path` / `is_safe_exec_path` | Refuse empty, NUL, CR/LF, other C0 controls (TAB allowed) |
| `run_argv_capture` | `fork` + `execvp`, no shell; validates **every** argv element |
| `run_argv_first_token` | First whitespace token of stdout; requires `ok && exit_code==0` |
| `shell_quote` | Validated POSIX single-quote (still used only where dock **must** use `sh -c` for env prefixes + redirection) |

Hash argv vectors (`md5`, `-q`, path) never reach a shell. Paths with spaces are safe under argv.

### A3 — `posebust::sha256_file` is still argv-backed (INFO, not a regression)

`flexaids::posebust::sha256_file` → `sha256_via_openssl` →

```cpp
run_argv_first_token({"openssl", "dgst", "-sha256", "-r", path});
```

So the “preferred” first hop is **also** argv-exec (openssl), then shasum/sha256sum. Still **no shell**, and `is_safe_exec_path` is checked both in the DatasetRunner lambda and inside the openssl helper. Not a security hole; naming may oversell purity.

### A4 — Dock command path unchanged (shell still present where required)

`SubprocessGuard::fork_exec` still uses `/bin/sh -c` for dock lines that need `ENV=…` prefixes and stdout/stderr redirection. Paths continue to go through `shell_quote` after `is_safe_exec_path` checks. **Out of this merge’s conflict surface**, but consistent with the dual model: argv for tools without shell metacharacters; quoted shell only when unavoidable.

### A5 — Dead / parallel leaf: `DatasetRunnerProvenance` (LOW)

`LIB/DatasetRunnerProvenance.{h,cpp}` already implements argv-safe `provenance_file_md5` / `sha256` and a slim writer (P1 split). This merge **does not call** that leaf from `DatasetRunner::run()`; it inlines helpers and uses `flexaids::write_run_receipt` instead (aligned with sibling merge note “keep RunReceipt run path” / `bf4617674` family).

**Impact:** duplication, not dual-write (only RunReceipt path runs). Risk is future agents re-wiring the leaf and double-writing divergent `provenance.json`. Prefer deprecating the leaf or making RunReceipt call into shared hash helpers.

### B4 — FINDING F1 — MEDIUM — `seed_elitism` in receipt disagrees with runtime for oracle

**Receipt (this merge):**

```cpp
bool receipt_seed_elitism = protocol_cfg_.seed_elitism;
if (config.mode == BenchmarkMode::ORACLE_CEILING) receipt_seed_elitism = true;
if (config.mode == BenchmarkMode::DEFINED_CLEFT_REDOCK ||
    config.mode == BenchmarkMode::AUTONOMOUS) {
    receipt_seed_elitism = false;

```

**Actual post-dock selection override (unchanged, same file ~6515–6518):**

```cpp
const int sel_elitism_ovr =
    (config.mode == BenchmarkMode::ORACLE_CEILING ||
     config.mode == BenchmarkMode::AUTONOMOUS ||
     config.mode == BenchmarkMode::DEFINED_CLEFT_REDOCK) ? 0 : -1;
// 0 → seed_elitism forced OFF in select_pose_freq_gated_pooled
```

| Mode | Receipt `seed_elitism` | Runtime `sel_elitism_ovr` | Match? |
|------|------------------------|---------------------------|--------|
| `ORACLE_CEILING` | **true (1)** | **0 (OFF)** | **NO** |
| `DEFINED_CLEFT_REDOCK` | false | 0 (OFF) | yes |
| `AUTONOMOUS` | false | 0 (OFF) | yes |
| unset / other | env / ProtocolConfig default | −1 (env/default) | usually yes |

`docs/implementation/protocol-config.md` (this merge) documents oracle ON — same as the receipt, **not** the Layer-1 selector.

Additionally, nested `protocol_config.seed_elitism` is the **raw env snapshot** (default true), so a single `RUN_RECEIPT.json` can contain:

- top-level `"seed_elitism": 1` (mode story for oracle),
- nested `"seed_elitism": true` (env default),
- while the process actually elected poses with elitism **off**.

**Impact:** provenance / C0 claim audits that trust receipt `seed_elitism` for oracle will **mis-state** the election rule. Does **not** change ranking behavior (receipt-only field).

**Fix direction (out of scope):** set `receipt_seed_elitism = false` for all three named modes to match `sel_elitism_ovr`, or record both `seed_elitism_env` and `seed_elitism_effective` with the latter derived from the same expression as Layer 1. Align docs.

### C2 — Env → ProtocolConfig → apply_config equivalence

**Historical (`814e86e58` `config_parser.cpp`):** mid-apply `std::getenv` for ranking/ablation knobs.

**Merged:** single snapshot at entry (`protocol` arg or `ProtocolConfig::from_env()` once).

| Knob | Unset behavior | Set behavior vs historical |
|------|----------------|----------------------------|
| `FLEXAIDDS_FORCE_CF_RANK_EMISSION` | JSON/default unchanged (`nullopt`) | Same truthy/falsey first-char rules |
| `FLEXAIDDS_CLASSIC_ENTROPY_RANKING` | unchanged | classic=0 → CF emission; classic=1 → entropy; **still applied after** FORCE_CF (same final precedence) |
| `FLEXAIDDS_ENTROPY_WEIGHT` | unchanged | `stod` override of `GB->entropy_weight` |

| `FLEXAIDDS_SHARING_ALPHA` / `BOOM_FRAC` | optional only when parseable | Same when set |

**Apply order for emission flags (preserved):**

```text
JSON force_cf_rank_emission
→ JSON classic_entropy_ranking=false forces CF emission
→ ProtocolConfig.force_cf_rank_emission if has_value
→ ProtocolConfig.classic_entropy_ranking if has_value  (wins last)
```

Matches historical getenv order (FORCE then CLASSIC).

### C3 — FINDING F3 — LOW — empty-string env edge case

Historical: `if (const char* e = getenv("FLEXAIDDS_N_ELITE")) GB->n_elite = atoi(e);` applied even for empty/`garbage` (atoi → 0).

New: `env_opt_int` returns `nullopt` for empty → **no override**. Invalid doubles for entropy weight similarly nullopt.

**Impact:** only pathological env (`FLEXAIDDS_N_ELITE=` empty). Normal claim scripts set numeric values. Ranking-neutral for production campaigns.

### C4 — Dual-protocol mitigation (PASS / science hygiene)

`apply_config` no longer calls `getenv` during apply; `top.cpp` snapshots once:

```cpp
const flexaids::ProtocolConfig apply_proto = flexaids::ProtocolConfig::from_env();
apply_config(config, FA, GB, &apply_proto);
```

Prevents mid-apply `setenv` races that could create dual-protocol engines. Receipt embeds the DatasetRunner snapshot (`protocol_cfg_`), not a second re-read at write time inside the receipt builder — good for “what the runner believed at start of `run()`”.

Note: child FlexAIDdS dock processes still re-read env at their own `top`/`apply_config` (subprocess model). That is pre-existing and correct for env-prefixed dock commands.

### C5 — Ranking claim language

Commit and PR body correctly state **override source path only**. CF remains a **contact-function scoring proxy**; receipt does not invent thermodynamic ΔG. Nested ProtocolConfig JSON may contain ranking ablation knobs for reproducibility without enabling them unless env/JSON set them.
