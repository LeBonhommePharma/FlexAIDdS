## 1. Executive summary

This merge lands **Bonhomme Fleet** (production resumable orchestration for `benchmark_datasets`) onto the **science residual stack** (ProtocolConfig, RunReceipt, DatasetRunnerStats/Provenance leaves, metal-on-`flexaid_core`).

Stated merge intent (commit body):

> Keep main CMake structure; wire FleetRunner into `benchmark_datasets` + FleetRunnerTests. Resolve add/add conflicts by taking full fleet sources.

**What went well**

1. **Ranking / scoring / election engines are untouched.** Diff vs first parent touches only `LIB/FleetRunner.*`, `LIB/benchmark_datasets.cpp`, and a Windows-only `LIB/top.cpp` hygiene fix — not `gaboom`, `Vcontacts`, `BindingMode`, clustering, or `DatasetRunner.cpp`/`.h`.
2. **Fleet is a control plane**, not a re-ranker: it pins binaries + protocol, leases shards, runs local compute, archives with tree SHA-256, and serializes **already-elected** DatasetRunner fields.
3. **Scientific reporting improves honesty** relative to the first-parent inline `write_fleet_json`: removes spurious `dG_mean` / `predicted_dG` aggregation; separates `execution_completed` from `success_rmsd` / `success_pb` / `claim_ready`.
4. **Metal wiring correctly prefers first-parent design** (bridges on `flexaid_core` + dependency targets) over second-parent’s re-attach of OBJCXX sources to `benchmark_datasets`.
5. **Astex native-85 JSON** loses machine-absolute `/Users/lp.more/...` paths in favor of manifest-relative paths (hygiene + portability).

**What failed**

1. **CMake conflict resolution drops first-parent science TUs:**
   - `LIB/DatasetRunnerProvenance.cpp` removed from `benchmark_datasets`, `test_dataset_runner`, `test_cofactor_blacklist`.
   - `LIB/RunReceipt.cpp` removed from `test_protocol_config`.
2. Those drops are **not compensated** by `flexaid_core` membership for Provenance (it is *not* in the core object library). RunReceipt *is* in `flexaid_core` / `LIB/CMakeLists.txt`, but `flexaids_add_unit_test` does **not** auto-link `flexaid_core` — so `test_protocol_config` still needs the explicit `.cpp`.
3. Minor merge scar: `flexaids_add_unit_test(test_protocol_config` loses indentation (valid CMake, noisy review signal).

### 3.2 Post-merge `FleetRunner` contract

**API** (`LIB/FleetRunner.h`):

- `ChunkMetadata` — campaign/chunk/attempt/worker IDs + runner/engine/manifest SHA-256 + command string.
- `serialize_chunk_result(metadata, BenchmarkReport, DockingConfig, duration_s)` — pure JSON string build.
- `write_chunk_result_atomic(destination, contents, error*)` — **no-overwrite**; POSIX `link` publish + `fsync`; refuses existing path.

**Serialization semantics (good):**

| Field family | Behavior |
|--------------|----------|
| Execution | `execution_completed` ⇔ `num_poses > 0 && !elected_pose_path.empty()` |
| RMSD success | `success_rmsd` passthrough |
| PB success | `success_pb` passthrough |
| Validators | SHA-256 cross-check of RMSD / PB / tENCoM pose digests vs elected pose |
| Claim | `protocol_claim_eligible`, `claim_ready` passthrough |
| Thermo | `shannon_entropy_nats`, `elected_h_vib_nats`, `thermo_available` — **no** fabricated ΔG mean |
| Election mirror | `elected_pose_*`, `elected_restart`, `elected_cluster`, `elected_cf`, `best_cluster_rmsd_a` |

Unit test `FleetRunner.SeparatesExecutionFromScientificSuccess` explicitly asserts:

- two completed executions can yield only one `success_rmsd` / `success_pb` / `claim_ready`;
- JSON must **not** contain `"dG_mean"`.

This is the right scientific language for a CF/proxy ensemble stack.

### 3.3 `benchmark_datasets` CLI wiring

New / required under `--fleet`:

```text
--fleet
--campaign-id --chunk-id --attempt-id --worker-id
--manifest-sha256 --runner-sha256 --engine-sha256
--output-json <file>   # not "-"
```

Guards:

- Missing metadata → exit 1.
- `benchmark=all`, prepare-only, list-codes, empty `--only-codes`, empty `--mode`, or stdout JSON → rejected.
- Empty results after run → exit 2.
- Atomic publish failure → exit 3.

Fleet does **not** re-dock, re-elect, or re-score: it calls the same `run_single_benchmark(...)` path as non-fleet, then serializes the `BenchmarkReport`.

### 3.4 Relative path resolution (manifest portability)

JSON pair loading now resolves relative receptor/ligand/site paths against the **JSON file’s directory** via `weakly_canonical`. Coupled with the Astex native-85 path rewrite, Fleet campaigns are checkout-portable. This does **not** change which structure files are used when paths already resolve to the same content.

### 3.5 Python control plane (`python/flexaidds/fleet.py`)

| Concern | Assessment |
|---------|------------|
| Binary pins | SHA-256 of runner, engine, and official `bust` verified before each claim |
| Protocol pins | mode, pop/gen, T, grid, threads, clustering, GPU, job timeout in immutable manifest |
| Seed policy | Forces `FLEXAIDDS_SEED_ELITISM=0`, `FLEXAIDDS_NATIVE_SEED_FRAC=0` |
| PB policy | Forces `FLEXAIDDS_POSEBUST_BACKEND=bust_cli` + pinned `FLEXAIDDS_POSEBUSTERS_BIN` |
| Oracle mode | `oracle-ceiling` **rejected** at plan time |

| Archive | `copy_tree_verified` + tree SHA-256; no overwrite of existing archive |
| Publish | `result.json` via `O_EXCL`; attempt records separate from accepted result |
| Aggregate | Target CSV of validator/election fields; rates for `success_pb` / `claim_ready` |
| Env allowlist | `SAFE_ENV_KEYS` only; rejects secrets-looking keys |

**Not exported** from `python/flexaidds/__init__.py` — entry is console script / direct module path (acceptable).

### 5.3 Fleet report path vs old inline JSON

First-parent `write_fleet_json` was actively **misleading** for ranking claims:

- Treated `r.success` + `predicted_dG` as primary stats (`dG_mean`, `dG_std`);
- Did not separate execution vs RMSD≤2Å vs PB pass vs claim_ready;
- Allowed overwrite / stdout fallback.

Merge Fleet JSON:

- Passthrough of DatasetRunner election fields (`elected_cf`, cluster indices, pose paths);
- Explicit **non**-claim of thermodynamic ΔG means;
- Immutable publish.

This **does not re-order poses**; it improves claim language fidelity.
