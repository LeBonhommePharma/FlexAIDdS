## Summary

This commit freezes a large **local campaign toolkit** for Astex Diverse cognate reproduction: double-fork Python launchers (v128c→v131 + 1G9V/1HQ2 specials), two shell wrappers (`run_full.sh`, `run_v128.sh`), offline RMSD scorers (`score_offline.py`, `score_reference.py`, `election_gap.py`), code lists, cleft QC, and partial poster-metric CSVs. Commit message correctly states it avoids embedding engine binaries or full result trees (parent gitignore excludes `engine/`, `full*/`, spheres).

**What works**

- Progressive protocol notes are rich (parallel-restart starvation, NO_SEC tradeoffs, PGO overhead, coarse_init, 1G9V HEM, multimer prune).
- Later Python launchers set `FLEXAIDDS_PARALLEL_RESTARTS=0` (serial restarts) — correct for the 18 GiB contract documented in comments.
- Base GA knobs are consistent: `pop=1000`, `gen=2000`, `job-timeout=10800`, `threads=1`, `omp-threads=1`, mode `autonomous`.
- `FLEXAIDDS_DATA_DIR` pin for energy-matrix provenance is well motivated in `run_full.sh` comments.
- `score_reference.py` is the stronger RMSD instrument (spyrmsd graph-isomorphism, heavy atoms, serial≥90000 pose selection, no superposition).
- `astex84_no1hq2.txt` matches embedded `CODES_84` (84 unique codes, no 1HQ2).
- Parent intentionally keeps staged Mach-Os out of git — good hygiene for binaries.

**What fails repro / claim correctness**

1. **Machine-absolute paths everywhere** (`/Users/lp.more/Projects/FlexAIDdS`) — violates `AGENTS.md` hygiene; scripts do not run on any other checkout.
2. **`run_full.sh` does not disable parallel restarts** despite documenting that default ON is the root cause of zero-pose targets — the handoff “resume” command re-creates the failure mode.
3. **Two scorers disagree systematically**; offline Hungarian is over-permissive (e.g. **1HP0 success flips** True offline / False spyrmsd).
4. **Poster metric is pooled any-pose ceiling**, not elected rank-0, not S_top10, **no PoseBusters** — conflicts with current claim contract language if read as benchmark success.
5. **Hard-coded ephemeral PID** (`V130_PID = 98837`), dual writers into `full_v130/`, and launchers that rewrite committed code lists.
6. **No binary SHA gate** at launch; engines are gitignored so “repro” requires undocumented local staging.
7. **Committed CSV `near=` columns embed absolute paths** (122 `/Users/lp.more` hits in the commit diff).

Overall: excellent **ops diary / campaign versioning**; **not a closed, portable scientific reproduction package** without path resolution, env fixes, and a single fail-closed metric path.

## Findings (with evidence)

### F1 — CRITICAL — Hard-coded machine-absolute `ROOT` / env paths (hygiene + portability)

**Evidence — every Python launcher:**

```python
ROOT = "/Users/lp.more/Projects/FlexAIDdS"
REPRO = f"{ROOT}/benchmarks/astex_repro"
# FLEXAIDDS_BINARY, DATA_DIR, CLEFT_SPHERE_DIR, ORACLE_SITE_DIR, CMD all derive from ROOT
```

Present in: `launch_v128c.py`, `launch_v128d.py`, `launch_v128e.py`, `launch_v129.py`, `launch_v130.py`, `launch_v130_1g9v_rerun.py`, `launch_v130_1hq2.py`, `launch_v131.py`, `launch_1g9v_chainfix_smoke.py` (7+ files).

**Evidence — shell wrappers:**

```bash
export FLEXAIDDS_BINARY="/Users/lp.more/Projects/FlexAIDdS/benchmarks/astex_repro/engine/FlexAIDdS"
export FLEXAIDDS_DATA_DIR="/Users/lp.more/Projects/FlexAIDdS/benchmarks/astex_repro/engine"
export FLEXAIDDS_CLEFT_SPHERE_DIR="/Users/lp.more/Projects/FlexAIDdS/benchmarks/astex_repro/spheres"
export FLEXAIDDS_ORACLE_SITE_DIR="/Users/lp.more/Projects/FlexAIDdS/benchmarks/astex_diverse/astex_diverse"
# ... absolute cache/output and absolute benchmark_datasets binary
```

**Evidence — committed result CSVs** embed the same absolute prefix in every `near` path (`poster_metric_reference.csv`, `poster_metric_results.csv`). Diff-wide count: **122** `/Users/lp.more` occurrences.

**Why it matters:** `AGENTS.md` → Repository Hygiene forbids machine-specific absolute paths in committed automation. Scripts fail immediately on any other user/clone (`os.execve` / bash path miss). Scorer CSVs are non-relocatable provenance.

**Fix recommendation:** Resolve repo root via `Path(__file__).resolve().parents[2]` (Python) or `git rev-parse --show-toplevel` / script-relative `$(cd "$(dirname "$0")/../.." && pwd)` (shell). Prefer `$FLEXAIDDS_ROOT` / `$FLEXAIDDS_LOCAL_ROOT` overrides. Store `near` as repo-relative paths. Run `python3 scripts/check_repo_hygiene.py` before re-commit.

### F2 — CRITICAL — `run_full.sh` leaves parallel restarts ON (reproduces zero-pose starvation)

**Evidence — script itself diagnoses the bug but does not fix it:**

```bash
# run_full.sh comments:
# ROOT CAUSE of the 11/16 "zero-pose" targets: all 10 restarts fork CONCURRENTLY
# (FLEXAIDDS_PARALLEL_RESTARTS default ON) and SHARE ONE per_job_timeout budget
export FLEXAIDDS_RESTARTS=10
export FLEXAIDDS_NO_SEC=1
# NO export FLEXAIDDS_PARALLEL_RESTARTS=0
```

**Evidence — engine default (ProtocolConfig):**

```cpp
// LIB/ProtocolConfig.h
/// Env FLEXAIDDS_PARALLEL_RESTARTS: if unset, defaults to (restarts > 1).
bool parallel_restarts{true};
```

**Contrast — fixed path:** `run_v128.sh` and all Python launchers set `FLEXAIDDS_PARALLEL_RESTARTS=0`.

**Handoff risk:** `HANDOFF_TO_GROK.md` tells the next agent to resume with:

```bash
bash benchmarks/astex_repro/run_full.sh
```

That re-enters the documented starvation regime (10 concurrent GAs on 18 GiB, shared 10800 s wall).

**Why it matters:** Primary resume script is **self-inconsistent**: comments describe ENV-ONLY fix needs, then omit the one boolean that Python launchers already set. Zero-pose / under-budget targets will reappear and be misread as engine defects.

**Fix recommendation:** `export FLEXAIDDS_PARALLEL_RESTARTS=0` in `run_full.sh` (and any other shell entry). Optionally refuse to start if free RAM < threshold. Align HANDOFF to the v128+ serial contract.

### F3 — HIGH — Dual offline scorers disagree; offline can flip success labels

**Metric claimed (both docs/scripts):** pooled over all restart poses; success = min RMSD **&lt; 2.0 Å** (explicitly *not* “10 best ranked”; more forgiving).

| Instrument | Selection | Atoms | Symmetry | Output |
|------------|-----------|-------|----------|--------|
| `score_offline.py` | PDB residue name tag ` f"{ligname} " ` | **All** SDF atoms (incl. H) | Element-blocked Hungarian | `poster_metric_results.csv` (19 rows committed) |
| `score_reference.py` | PDB serial **≥ 90000** | **Heavy only** | spyrmsd graph-iso (PoseBusters-grade) | `poster_metric_reference.csv` (84 scored, 19 successes) |

**Evidence — success flip on overlapping set:**

| PDB | reference (spyrmsd) | offline (Hungarian) |
|-----|---------------------|---------------------|
| **1HP0** | min=**2.221**, **False** | min=**1.600**, **True** |

**Evidence — large RMSD deltas (same pool, both tools):** e.g. 1JJE 4.22 vs 2.51 Å; 1L7F 4.63 vs 3.27 Å; 1M2Z 5.52 vs 2.75 Å (≥16 targets differ by &gt;0.05 Å among the 19 offline rows).

**Additional offline defects:**

- Ligand selection by residue-name substring is fragile for numeric/standard-residue ligand names (exactly the failure `score_reference.py` documents and avoids).
- No heavy-atom filter → nonstandard docking RMSD.
- `cf_of()` defined but unused dead code.
- Glob `{pdb}_[0-9].pdb` only single-digit ranks (OK if MAXRES emits 0–9 only; breaks if rank ≥10 ever appears).

**Why it matters:** MONITORING.md points operators at `score_reference.py`, but `score_offline.py` and partial `poster_metric_results.csv` remain in-tree. A careless “success rate” read of the offline CSV **overstates** 1HP0 (and potentially others). AGENTS.md requires inspect-first; two instruments without a single source of truth invite claim drift.

**Fix recommendation:** Delete or clearly mark `score_offline.py` as deprecated; make `score_reference.py` the only admitted path. Add a unit test on a frozen tiny pose set asserting spyrmsd values. Never commit absolute `near` paths.

### F4 — HIGH — Claim metric is pool ceiling, not method-reported election; no PoseBusters

**Evidence — scorer docstring (honest but non-claim-grade):**


**Evidence — election analysis exists separately** (`election_gap.py`) and correctly distinguishes:

**Evidence — AGENTS.md / benchmarking skill (current policy):** PoseBusters (or NativePoseQC) is mandatory for benchmark success; RMSD-only is not enough. Neither scorer runs PB/`bust`/NativePoseQC.

**Fix recommendation:** Rename columns to `pool_min_rmsd` / `pool_success_rmsd_only`. Report elected metrics as primary. Wire PoseBusters (or native QC) as a second gate before any external claim table.

### F5 — HIGH — `election_gap.py` path + atom-count contract bugs

**Fix recommendation:** Align pose parsing with `score_reference.pose_coords` (full SDF nat → heavy mask). Resolve paths from `__file__`. Guard empty `rows`. Prefer one shared RMSD library module.

### F8 — MEDIUM — `FLEXAIDDS_ORACLE_SITE_DIR` naming vs handoff “no oracle leakage”

**HANDOFF:**

```text
Protocol: --mode autonomous, GetCleft cavity-confined (FLEXAIDDS_CLEFT_SPHERE_DIR),
NO oracle leakage (0 ORACLE/COGNATE injects verified)
```

**Scripts always set:**

```bash
FLEXAIDDS_ORACLE_SITE_DIR=.../astex_diverse/astex_diverse
```

**Engine semantics (DatasetRunner `fetch_astex`):** `ORACLE_SITE_DIR` supplies **`_binding_site.pdb`** for LOCCLF / site centroid (and hard-aborts if 0 sites). That is **known-site pocket definition**, not necessarily crystal-pose gene injection (`ORACLE_CEILING` / `FLEXAIDDS_COGNATE_SITE` / `[ORACLE-DIRECT]` are separate).

**Why it matters:** Correct for cognate pocket redock with GetCleft spheres, but the env name + handoff wording invite “oracle-free” overclaims. Pocket is crystal-informed.

**Fix recommendation:** Keep the env (required for Astex prepare), but handoff language should say “autonomous GA / no crystal pose seed; site from binding_site + cleft spheres” rather than bare “NO oracle leakage.”
